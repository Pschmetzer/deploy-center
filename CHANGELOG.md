# Changelog

## Unreleased

- Security (CLI): `af_mask` now covers Google OAuth (`ya29.`, `GOCSPX-`), Shopify, PyPI, Docker, Twilio, Mailgun and 1Password tokens, `curl -u user:pass`, passwords with spaces, escaped quotes and a `/` inside a database password; journal details are masked when written; hook URLs are refused for every spelling of a private IPv6 address (`0:0:0:0:0:ffff:7f00:1`, `::127.0.0.1`); a Heroku, Netlify or Cloudflare API base that is not `https://` is ignored.
- CLI fixes: `deploys certs` and `Retry-After` dates are read with the C locale (they failed under `de_DE`); the shared team window over midnight (22:00–06:00) belongs to the day it started and each window of a list reads its own time zone; `ghpages` finds the run of its own `workflow_dispatch` (not a parallel push run); `team list` without repos exits 0; `team add ../x` is refused; `creds` says "not set up" (exit 0) for a provider without a key and "NOT accepted" (exit 1) only for a refused key; `<command> --help` for an unknown command exits 2.
- Local session counter: `deploys local-sessions [--json]` lists the Claude Code sessions on this Mac (title, folder, idle time, CPU, RAM) and finds tasks that should have been bundled: more than 3 sessions on one repo, each started within 10 minutes of the one before, and the same task running twice; two sessions in one folder and sessions idle for over an hour are flagged too. The count turns yellow only at 30 (`deploys local-sessions set max-local|bundle-to|burst-min`). The menu shows the count with a green or yellow dot and a "Bundle tasks" menu with the extras; ending a session always asks first (`deploys local-sessions stop <pid> --yes`). Read-only MCP tool `deploys_local_sessions`. The number of running cloud sessions cannot be read on the Mac; `deploys sessions` shows them as GitHub sees them ([docs/LOCAL-SESSIONS.md](docs/LOCAL-SESSIONS.md)).
- Performance guard: a Docker stack that is started again after an idle stop is left alone for 24 hours instead of being stopped again on the next pass.

- Cloud sessions: `deploys sessions` and a "Cloud Sessions" window (menu bar → Cloud Sessions) show which Claude Code cloud sessions finished, wait or seem stuck, read from GitHub (session branches `claude/…`, their pull requests and the `Claude-Session` commit trailer). A Mac notification when sessions are merged ("room for 2 new ones"), when a pull request waits and when a session seems stuck. Repos to watch: `deploys sessions add <owner/name>` (kept in `sessions.json` in the config folder). New read-only MCP tool `deploys_sessions`.

## 0.14.0 - 2026-11-25

### Highlights

- Performance guard: how full the Mac is as a green, yellow or red dot in the menu bar, heavy checks that wait for room (`deploys perf gate` and a Claude Code hook), hung and orphaned process trees stopped, Docker stacks stopped and woken with a click
- Vercel token in the keychain (`deploys vercel set-key`); costs and the budget brake read Vercel charges again
- New commands: `deploys preview`, `domains`, `forecast`, `env-diff`, `group`, `prepare` and `self-update --check`; eight more read-only MCP tools
- Mac app: owner check asks for Touch ID for more actions; the menu bar says what waits and what failed
- Faster and steadier with hundreds of projects (`deploys changed` no longer hangs on macOS bash 3.2)

### All changes

- Mac app: the performance guard's green, yellow or red dot now shows in the menu bar (it is drawn into the icon; a second image next to it was dropped by macOS).
- Mac app: the main window shows how full the Mac is next to the build costs ("Mac: room to spare", busy, overloaded); a click opens a panel with the reason, the biggest consumers, the processes and the Docker stacks, each with Stop or Wake.

- Hook sites: a name that cannot be looked up is refused instead of passed on to curl unchecked (use `--allow-private` to keep the old way); the private-address list now also covers 198.18.0.0/15, multicast and reserved IPv4, NAT64, 6to4, Teredo, documentation and site-local IPv6.
- Fix: since the Vercel token change, `deploys costs` read no Vercel charges and the budget brake of `deploy-changed` did not hold (the token helper was missing in the parallel cost reads). The keychain is also read once per run and never from the caller's input.
- Vercel: `deploys vercel set-key` keeps a Vercel token in the keychain (`deploy-center-vercel`), and every `vercel` call of deploys gets it in its environment (never as an argument). The CLI login renews itself on each run; several runs at once could lose that race and open a browser "Authorize Device" page nobody asked for. Without a token the CLI login is used as before.
- Performance guard: `deploys perf status` shows how full the Mac is (memory pressure, swap-out rate, load, the biggest consumers), `deploys perf gate` and a Claude Code hook hold heavy checks until there is room, `deploys perf clean` finds orphaned dev processes and test browsers, `deploys perf reap` sorts every process class (checks, test browsers, MCP servers, npm exec, dev servers) into in use, hung, orphaned or unused and stops hung and orphaned trees, `deploys perf consumers|stop|wake` shows Docker stacks, simulators and caches and stops or wakes a Docker stack (never its data; idle stop is opt-in), and the menu bar shows a green, yellow or red dot. MCP: `deploys_perf`. Docs: docs/PERF.md.

- MCP: four more read-only tools over the journal commands: `deploys_health`, `deploys_weeks`, `deploys_streak` and `deploys_when`.
- Mac app: with the owner check on, showing the iPhone QR code, switching an account, running Autofix by hand and turning the nightly check off ask for Touch ID too; a log line "exited with 0" is no longer taken for the error; a failed deploy keeps one notification per project instead of a pile.
- Fix: `deploys changed`, `plan` and `ai` hung for minutes with a few hundred projects on the macOS bash 3.2: a whitespace check on the whole list was quadratic. It is a glob match now (`nonblank`).
- Tooling: `scripts/bench.sh` closes stdin and stops a run after `BENCH_TIMEOUT` seconds (default 120), and the CI step has a 10 minute limit; a hanging benchmark no longer cancels the whole test job.
- Two-person rule: an approval (review or `deploy-approved-by:` label) only counts from an account that may push to the repo (admin, maintain, write); triage and read-only accounts, and accounts whose permission cannot be read, no longer count. An issue counts for a commit only when it names at least 12 characters of its sha (7 matched by accident).
- Tests: the VS Code test that registers the commands no longer fails now and then on Linux (the temp folder was removed while the CLI still wrote into it); removing it is retried.
- Fix: `deploys fly set-key` saved a `FlyV1 …` token with its space unquoted, so the keychain kept only `FlyV1`; it is quoted now.
- Widgets: the saving ("≈ $12/mo saved") and the times follow the language of the app, not the system language, as the texts do.
- MCP: four new read-only tools over existing commands: `deploys_domains`, `deploys_forecast`, `deploys_env_diff` (names only) and `deploys_preview` (framed as untrusted data).
- Mac app: "Copy for Claude" masks secrets before it cuts the log, so a private key that begins above the excerpt no longer slips through; a token limit like "1,5m" is 1.5 million, not 15 million.
- Tooling: `scripts/check-build.py` (and a CI step) fails when `Package.swift` and the release build name a different minimum macOS or Sparkle version.
- Mac app: times and dates in the window, rows, toasts and the quiet-hours picker follow the app language, not the Mac's region; "1 project copied" and "1 message cleared" use the singular; the Autofix PR link goes through the safe-link check; "Show the first-start guide again" is greyed out (with a hint) while no project builds on every push.
- New: `deploys clean` frees disk space held by old git worktrees: build output (`node_modules`, `.next`, `dist` …, only what git ignores) in worktrees unchanged for 2 days, and with `--worktrees` whole worktrees that have no changes and are merged into `origin/main` (`git worktree remove`, the branch stays). Without `--yes` it only reports. `deploys clean schedule on` runs it daily when the disk runs low. Folders in `~/.config/deploys/clean.json` (`{"roots":["~/Code"]}`).
- Autofix: the hand-over caps (default 6 a day, 2 per project) can be set for good in `~/.config/deploys/autofix-limits.json` (`{"perDay": 20, "perProject": 5}`); `0` means no cap. The environment variables still win.
- Guard: the notification says why auto-deploy was turned off ("its allowance ended", or "auto-deploy was on and no allowance covers it") and what went wrong when a switch failed (the first error, short, tokens masked); `guard status --json` has a `reason` per action.
- Fix: `deploy-changed --yes` that could not read anything names a closed deploy window first again (it said "Could not tell" before the window was checked).
- Mac app: "Link repo …" on a project without a Git source names its repo (stays on this Mac) so its commits show; hovering a waiting project shows who pushed, when and how many files changed. The two figures of the savings banner open popovers that show where they come from.
- Fix: `deploy-changed --yes` in a closed deploy window stops with the window's reason before it reads any platform (since the "no platform is on" stop it said that instead).
- Website: `scripts/check-a11y.py` (run by CI) checks WCAG 2.2 AA basics on every page and on the color tokens: contrast of text, links and buttons in dark and light, a skip link, one `<main>`, labelled navs, heading order, form labels, names of links and buttons, and reduced motion. Docs tables without a header row now mark the first cell of each row as a row header for screen readers.
- `deploy-changed --yes`: a closed deploy window now stops it before any platform is asked (it said "could not tell" first when nothing could be read).
- `deploys self-update --check [--json]`: says whether a newer CLI release is out and prints the command that updates this copy (install script, Homebrew or Docker). It only checks: nothing is downloaded or installed. Exit 10 means an update exists, 1 means the release list could not be read (offline, proxy).
- Fix: `deploy-changed --yes` in a closed deploy window says "No deploys now" again before it reads any platform; a run with no platform on ended with "Could not tell what has changes" instead.
- Examples: four presets (`examples/presets/`: solo, agency with 20 client sites, monorepo with previews only, student budget), and two `hooks.d` examples: `pre-deploy-backup` (saves your settings before a start) and `post-deploy-smoke` (asks a URL after a start). `tests/examples-tests.sh` checks them all with no account.
- Mac app: the menu bar says "5 waiting, 2 failed" and lists the failed projects; the "Claude found" hint says what connecting gives and never comes back after you close it.
- `deploys prepare on 08:30 --when-green --no-freeze`: a conditional morning job that gets a deploy ready and starts nothing, unless `--yes` is stored in the entry (and never through a closed deploy window).
- `deploys group`: your own ordered groups ("first api, then web"); a run waits for each member and stops at the first failure, and never starts without `--yes` or a "y" on a terminal.
- `deploys env-diff <project>`: environment variable names in production but not in preview (Vercel), names only, never values.
- `deploys forecast`: this month's build cost so far, projected to month end and shared by project (an estimate), with a warning near the `budget` limit.
- `deploys domains [--warn 30]`: custom domains apart from the platform's own addresses, with the days their certificate has left; exit 1 inside the threshold.
- `deploys preview <project>`: what a production deploy would do (waiting commits, files, risk check, matching rule, deploy window, budget, verdict) in one view; it starts nothing.
- Speed: reading a list of 200 projects with their GitHub state starts about half as many `jq` and `tr` processes (the repo name, the cache name and the pull request count are worked out without them), 4.1 s to 3.0 s in `scripts/bench.sh` on a Linux container; the output is unchanged (`tests/perf-tests.sh`). `scripts/bench.sh` times the CLI against a made-up platform with 200 projects.

## 0.13.0 - 2026-11-23

### Highlights

- Nightly security check on every repo (OSV-Scanner, gitleaks, Semgrep), with a history view and freeze import from an ICS calendar
- Mac app: shortcut sheet (⌘/), why-is-this-waiting line per row, error-pattern hints, cost forecast, several accounts per host, health score
- iPhone app: timeline of recent deploys, failure-cause hint, open outages, Dynamic Type rules
- New host Northflank (opt-in); Koyeb and Deno Deploy read every page; more reliable times and escaped keys on other hosts
- Timeline and recovery in MCP, Raycast, Alfred, the widget and VS Code; German docs for every page, a troubleshooting page and a security model page

### All changes

- `changed`, `deploy-changed` and `plan`: when no platform could be read at all, they now stop with the error (exit 1) instead of printing a stray table header, "Would deploy these .", `command not found` lines or a jq error (exit 2).
- Budget: when Vercel billing gives no answer at all (no key, not logged in), `deploys budget` and `deploy-changed --yes` now say the spending could not be read (a warning, or a stop with `--strict`) instead of ending with a jq error.
- Widgets: while a build runs the widgets look again every 5 minutes (instead of 30), and once the picture is out of date (the app has not run for three hours) every hour, which spares the daily reload budget.
- iPhone app (fix): a cancel of a followed deploy that came too late (the deploy had finished) no longer hides the failure of a later canceled build of the same project.
- Providers (security): Heroku and Railway escape the key in the curl config line like the other hosts do, and refuse a key with a line break in it without sending anything; before, a quote or line break in `HEROKU_API_KEY` or `RAILWAY_API_TOKEN` could add curl directives.
- iPhone app (Dynamic Type): the four numbers above the list and the "Recent deploys" rows follow one set of rules, tested for every text size; at accessibility sizes the time moves under the project name and titles are no longer cut off.
- Providers: Deno Deploy lists every project of the organization, not only the first 100 (it reads the next page while a page is full).
- Website: a guide (English and German) for `deploys doctor` and `creds`.
- `deploys ignore`: a damaged `ignored.json` is named and left alone (exit 1) instead of ending with a jq error, a stale lock and a temp file.
- Providers: Koyeb lists every service, not only the first 100 (it reads the next page while a page is full).
- AI usage: a damaged `ai-usage.json` no longer makes the monthly token cap count nothing for ever (it starts again), and no temp file is left behind.
- Fix: `deploys exit-codes` printed the rest of the script after its table; it now prints only the table.
- Docs: `DEPLOYS_ANTHROPIC_API` (the address `deploys ai` talks to) is in the CLI reference and the man page; CI now fails when a `DEPLOYS_*` variable the scripts read is named in no docs page.
- Providers: Deno Deploy, Firebase Hosting, Fly.io, GitHub Pages, Heroku, Koyeb and Railway read a time written with an offset (`2026-11-05T12:00:00+02:00`) correctly; before, the row had no "last deploy" time. Z times, with or without fractions, are unchanged.
- iPhone app: "Recent deploys" (clock button above the list): the deploys of all projects in one timeline, newest first, grouped by day (today, yesterday, then the date) for the last 7 days, with the failures of each day counted. Read only; works offline from the last history read.
- Website: guides (English and German) for `deploys certs`, `idle` and `metrics`.
- CLI: per-project overrides in `rules.json`: `"overrides": {"vercel/docs": {"minAgeHours": 1, "skip": ["api waits a day"]}}` changes a number or flag a rule already has for that project (a pattern like `vercel/*` works too) and `skip` switches named rules off for it; `rules check` says "the rule is switched off for ...". Overrides add no new conditions.
- CLI: `freeze import` closes only the evening of an event that ends at midnight of the next day (it used to close both days).
- Fix: `DEPLOYS_CI_IGNORE` now leaves out check runs by name (GitHub Actions jobs), not only commit statuses, so an optional check that is always red no longer blocks `deploy-changed --when-green`.
- Docs: the website's Hosts section now has Fly.io, Railway, Heroku, Firebase Hosting, GitHub Pages, Koyeb and Deno Deploy and the table of what each host can do; the README host lists (also the German one) name every provider.
- Docs: German versions of Autofix, Bug scan, Safe deploys, Team mode, GitLab, Claude in the app, Claude Code, Widgets and iPhone, Adding a host, Adding a git host and Uninstall (`docs/*.de.md`); README.de.md links them.
- Docs: a guide for moving from auto-deploy to one deploy a day (`docs/MIGRATING.md`) and a plain-language security model page, both also in German.
- Providers: Northflank (`deploys providers enable northflank`, off until turned on). It lists the services of every project with the state of their newest build and starts a build of a service's branch, or of a given commit with `--sha` (needs `--yes`). Services that only run an image are shown, not deployable. Token from `NORTHFLANK_TOKEN` or the keychain. Tested with fixtures only.
- iPhone app: notifications of one project stack together and the stack's summary line names the project (not with "Unlock on open", where the lock screen names no project).
- iPhone app: a failed build's log starts with a "Likely cause" hint (out of memory, a missing module, a dependency conflict, a missing command and more), and a documented error (same phrases as the Mac app) links to the troubleshooting guide.
- CLI: `deploys nightly history [--limit N] [--json]` shows what each nightly run did (when, how long, repos, new findings and leaks, failing checks, whether it notified); the last 90 runs are kept, a run with no repos counts too.
- CLI: `deploys freeze import <calendar.ics> [--dry-run]` turns a calendar (all-day and timed events, folded lines, CRLF) into closed dates in `window.json`. Events that are over and repeating events are left out (and counted); an event in UTC or over several days closes whole days; importing twice adds nothing; a file that is no calendar changes nothing.
- Mac app: ⌘/ lists all keyboard shortcuts, grouped per window (also under the View menu).
- Mac app: the ticked projects of each tab are remembered between launches.
- Mac app: a project that waits to go live says why when it knows (closed deploy times, a hold rule, the queue, a missing key, observer mode).
- Integrations: MCP tools `deploys_timeline` and `deploys_recovery` (read-only), a Raycast command and an Alfred filter (`dct`) for the timeline, a widget "Open outages" (failed deploys and since when), and a VS Code status bar item for open outages.
- Website: guides (English and German) for `deploys timeline`, `recovery`, `when`, `streak` and `digest`.
- Platform calls: a `Retry-After` that is huge or has a leading zero (`08`) no longer breaks the wait check; a wait over a minute is now reported as such.
- Exit codes: a wrong call (`Usage: …`, an unknown option or command) now ends with 2 in every command, as docs/CLI.md says; it was 1 in many.
- Journal: an entry written after a crash that cut the last line short is no longer glued onto that broken line (it was lost with it).
- Known build failures (out of memory, lockfile out of date, wrong Node version, missing environment variable, 401/403) get a hint with the usual fix and a copy button under the log; failed builds with the same cause across projects are grouped in Settings > Platforms.
- Costs sheet: a forecast for the month per project with a warning when a project's budget will be passed, and what a project would cost on the other host (your prices per build minute, `deploys price`).
- Several accounts per host (Settings > Platforms): keys only in the keychain, one click to switch.
- Health score per project (0-100, the formula of `deploys health`) in Settings > Platforms; the weekly report compares this week with the week before; the iPhone app shows open outages and the average health.
- New read-only commands: `deploys health` (0-100 per project from failure rate, recovery time, age of the last deploy and CI; the formula is in docs/CLI.md), `deploys weeks` (the last week against the one before) and `deploys export` (journal and costs as CSV or JSON, fixed columns, secrets masked, files private).

- Nightly check (Settings > Claude, `deploys nightly`): OSV-Scanner, gitleaks and Semgrep on every repo once a night; the first check of a repo is its starting point, then only new findings count, one notification. Optional: Claude gets only the new findings in a bug scan that opens a PR (at most 2 a night, never merges or deploys). Leaked keys are only reported. Optional weekly review: once a week Claude reads each repo's changes since its last review and looks for bugs they brought in (shares the nightly limit with the fixes). All switches are off by default.

## 0.12.0 - 2026-11-21

### Highlights

- Five new hosts: Fly.io, Railway, Heroku, Firebase Hosting and GitHub Pages (opt-in)
- CLI: `watch --json`, `digest`, `streak`, `timeline`, `config export` and `import`
- Mac app: filter chips above the list, a 401/403 check after a deploy, clearer palette commands
- iPhone app: offline use, Live Activity and Shortcuts
- Website: 11 new guides, security.txt and better search

### All changes

- Tests: more cases for the team repo field (trailing slash, ssh address, letters beyond ASCII, empty) and for the quiet-hours digest at the end hour.
- Mac app (accessibility): decorative symbols (pin, queue hourglass, CI and risk marks, empty-state icons, quick-filter chips, command-palette rows, connection status) are hidden from VoiceOver, so it no longer reads symbol names next to the text that already says the same.
- Mac app: in a build log, the "previous / next / first error" buttons sit in a bar under the log instead of covering its last lines.
- CLI: `deploys streak` shows, per project, how many deploys in a row went without a failure (now and the longest in the window; reads the journal only). `deploys note <project> "text"` writes one line into the journal that shows in `deploys timeline` (a text that looks like a secret is refused, nothing on a platform is touched).
- CLI (watch and verify): `deploys watch` has `--json` (one line at the end; `phase` tells failed from canceled), `--interval`, `--quiet`, a little jitter between asks, a longer wait after a 429, shows why a platform could not be asked and stops at once (exit 3) when the key is refused (401/403); `watch a --and b` runs at most six at a time and Ctrl-C stops them all and removes its temp folder. `deploys verify` can check the answer's text (`--match`), a header (`--header`), the TLS certificate (`--cert-days`), wait for a fresh service (`--warmup`, `--retry-connrefused`), runs several checks at the same time, says why there was no answer (DNS, refused, timeout, TLS) and counts down in a log file without carriage returns. Global `--quiet` and `--debug` (a trace of the calls, secrets masked); `deploys exit-codes`; a missing argument is exit 2 (`die_usage`), not 1; `--force` no longer takes the next option as its reason; under `bash -x` the key and the autofix token stay out of the trace.
- CLI (more): `deploys config export` and `config import` (settings without keys; import checks the file, says what changes, writes only with `--yes`); `digest`, `simulate` and `ledger` take `--format markdown`; `metrics` has `deploycenter_up` and `deploycenter_scrape_timestamp_seconds`; `hooks install --hook pre-commit` stops a commit that adds a key or token, asks for `--yes` when `core.hooksPath` is global, and `hooks status` names a `pre-push.local` that is not executable; completion (bash, zsh, fish) finds the command after `--json`, offers the flags of the commands and provider verbs, has a built-in list when the script cannot be read and quotes the config folder; Cloudflare reads all pages of the project list by `total_pages`; a GitLab list of merge requests is read once at the end; big lists of projects no longer hit "Argument list too long"; fewer parallel reads while GitHub's budget is low (`DEPLOYS_PARALLEL`); a stale `deploys.*` temp file of a killed run is swept once a day; exported shell functions go only to the readers that need them; `release.sh` refuses a `.release.env` others can write, replacing a published release (`--force-republish`) and `--check-addons --dry-run`, reads `## v0.7.0` notes and cleans up its temp files. Moved out of `deploys` into `lib/` (verify, watch, completion, risk rules, hook runner) to keep it under its size ceiling; `scripts/check-bash32.sh` and `scripts/check-disables.sh` guard bash 3.2 and the `shellcheck disable` count; `check-public.sh` now knows every prefix of the log masker.
- CLI (security): a hook URL with `user@` in front of the host (`https://evil.com@127.0.0.1/x`) is refused; the host name of a hook is looked up, refused when it points at a private address (also through `nip.io` or a DNS answer that changes later), and curl is told to use the address that was checked. `deploys hook add --status-url` names an address that reports the state of the last build (`hook status` shows building, ready or failed from it). A failed trigger that cannot have started a build (no connection, a 4xx answer) no longer blocks the next try for a minute. HTTP calls to the platforms quote the key in curl's config, refuse a key with a line break (without printing it), remove their temp files on Ctrl-C, ask a POST again when the host was not found, read `Retry-After` as a date, give up with a hint when it asks for more than a minute, keep to a total time (`HTTP_DEADLINE`, 120 s), mask secrets in an error body, name what was not found on a 404, and print a trace of method, path, status and time with `DEPLOYS_HTTP_TRACE=1` (no headers, no body, no query).
- Mac app: a command-palette command that cannot run (observer mode, a project that is already running or cannot be deployed) says why in a toast instead of closing in silence.
- Mac app: the failed-builds log search puts the cursor in the search field, has Reload and says when the logs were read and how many could not be read, notes the 20-lines-per-project limit and can copy a group's error line.
- CLI: three read-only views of the journal. `deploys timeline` lists what happened (deploys, failures, rollbacks, forced starts) newest day first, `deploys recovery` shows how long each failure lasted until the next deploy of the project (typical and longest time, outages still open), and `deploys when` shows on which weekday or hour of the day your deploys failed more often (a hint from your own history; slots with fewer than five tries are marked).
