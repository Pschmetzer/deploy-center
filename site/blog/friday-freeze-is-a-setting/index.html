A Friday freeze should be a setting, not a rule

A rule that says "no deploys on Friday afternoon" works until someone is in a hurry. A setting that refuses the deploy does not depend on memory, and a reason you must type for the exception turns a quiet bypass into a record.

Last updated 20 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

Why rules fail and settings hold

A team agrees not to deploy late on Friday. The agreement lives in a chat message and in people's heads. The day it matters, the person who deploys is tired, wants the fix out and has forgotten the agreement, or remembers it and decides this one is small.

A file does not forget and does not decide. In Deploy Center, window.json lists the times when production deploys are refused. The agreement is then something the tool enforces and the team can read in one place.

The exception is where the value is

A freeze with no way out gets bypassed in a worse way: someone turns the tool off. So give it a front door. deploys deploy-changed --yes --force "reason" starts the deploy anyway, and the project gets a forced entry in the deploy history with the window and the reason. Next week you can read which Friday deploys happened and why, instead of guessing.

This changes the question from "did anyone break the freeze?" to "was that a good reason?", which is the one worth discussing.

What stays open on purpose

Rollbacks, previews and verify still run inside a closed window. A freeze that blocks a rollback makes an incident longer, and the point of a freeze is fewer incidents. If a deploy that slipped through is broken, deploys verify can roll it back by itself when the site answers 5xx. See the guide on the health check.

Close the side doors

The window guards deploys started with Deploy Center. A push that your host deploys on its own never asks the window. If auto-deploy is still on, the freeze is a polite suggestion. Turn auto-deploy off on the host and let the guard turn it off again if it ever comes back; then every production deploy goes through one door. The guides on stopping push builds list the switch per host.

A small start

Begin with one rule, { "days": ["fri"], "from": "15:00" }, and the dates of your holidays. Add the weekend only if nobody is on call. Read the journal after a month, and move the line where the exceptions pile up. See set up a deploy freeze for the file format.

Questions

Is a deploy freeze the same as no deploys?

No. It refuses production deploys inside the window. Previews, rollbacks and verify still run, and a deploy with --force and a reason goes through.

Does it stop my host's auto-deploy?

No. It only guards deploys started with Deploy Center. Turn auto-deploy off on the host so production deploys go through it.

Where is the reason for a forced deploy kept?

In the deploy history, the app's journal, with the window and the reason.

Can I run it from a script?

Yes. deploys window exits 1 while the window is closed.
