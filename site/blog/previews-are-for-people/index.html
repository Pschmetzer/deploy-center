Previews are for people: a policy for bots and agents

A preview build is useful when a person opens it. A bot's branch and an agent's intermediate pushes build previews that no one looks at. Keep previews for the pull requests people review, and skip them for everything else.

Last updated 20 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

What a preview is for

A preview lets a reviewer click through a change before it ships. The value is in the click. Without it, a preview is a build that cost minutes and produced a URL nobody visited.

Bots and agents break the link between a build and a person. Dependabot and Renovate open branches for dependency updates; a coding agent pushes after nearly every step. Each push to a connected repository builds a preview for every project connected to it.

The policy

  1. People's pull requests get a preview. That is where review happens.
  2. Bot and agent branches do not, by branch prefix such as dependabot/, renovate/ or your agent's own prefix.
  3. An agent's work gets one preview at the end, from the pull request you open for it, not one per push.
  4. Anything risky gets built by hand, on purpose, when you decide.

Each host has its own way to write the rule: an Ignored Build Step on Vercel, an ignore script on Netlify, a preview setting on Cloudflare Pages and Render. See the guide for Netlify, Cloudflare and Render.

See what exists

deploys vercel previews web    # newest preview per pull request, with its URL
deploys hooks install          # before a push: which builds it would start

previews is read only and works for Vercel, Netlify and Cloudflare Pages. The pre-push hook is a way to notice a build before it starts.

What the policy costs

A bot pull request without a preview is reviewed from its diff and its CI. For a dependency update that touches build output, build the preview by hand. That is one build you chose instead of one per push. The same logic applies to agents that push many times.

Questions

Does this also stop production builds?

No. It is about previews. For production, turn auto-deploy off and deploy when you decide.

Will pull requests from people still get previews?

Yes, as long as their branch does not match a bot prefix in your rule.

What if my agent pushes straight to main?

Then production builds on every push. Turning off auto-deploy matters most there.

Does Deploy Center start previews?

Where the host has them: deploys deploy <project> --preview for Vercel, Cloudflare Pages and AWS Amplify.
