How it is calculated

with auto-deploy   = projects × pushes per day × cost per build × 22
deploying by hand  = projects × min(deploys, pushes) × cost per build × 22
saving             = with auto-deploy − deploying by hand
  • 22 working days a month. Weekend pushes add to the first line.
  • One build per project per push. If several projects are connected to one repository, a push builds each of them; count them as separate projects.
  • Previews count. Pushes to any branch build a preview on Vercel. Include them, or set the sliders for production only.
  • Nothing leaves your browser. The numbers stay on this page; the share link only contains the four slider values.

Find your cost per build

  1. On Vercel, open the team's Usage page and read the build cost for the last month. On Render, read the build minutes on the Billing page.
  2. Count the builds in the same period in the Deployments list.
  3. Divide the cost by the number of builds.

Deploy Center shows the Vercel build spend of the last 7 days and the monthly pace in its window, so you can check the estimate against real numbers.

What this does not include. Function, image and bandwidth costs do not change when you deploy less often. Plans that include some build time make the first builds of a month free. The result is an estimate, not a quote.

Questions

How much does a Vercel build cost?

It depends on your plan, the build machine and how long the build runs. Divide last month's build cost on your usage page by the number of builds to get your own number.

Why compare with deploying by hand?

Most pushes do not need to go live on their own. If one deploy at the end of the day ships all of them, you pay for one build instead of one per push.

Does this work for Render?

Yes. The formula is the same; use Render's build minutes and price for the cost per build.

Is anything sent to a server?

No. The calculator runs in your browser. The share button opens a post with your numbers only if you click it.
