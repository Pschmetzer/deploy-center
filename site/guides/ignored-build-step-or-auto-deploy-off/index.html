Ignored Build Step or auto-deploy off: which one fits?

Use an Ignored Build Step when most pushes should still build and you can describe the exceptions in a script. Turn auto-deploy off when you want to decide when production goes live: a push starts nothing, and you deploy what changed in one step.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Both stop a push from costing a full build. They work in different places: the Ignored Build Step is a script Vercel runs before each Git build, and turning auto-deploy off in Deploy Center removes the project's Git connection, so a push starts nothing. This page lines them up. Script examples are in Vercel Ignored Build Step: script examples and pitfalls.

When the Ignored Build Step fits

  • You want previews on feature branches and only need to leave out a few: bot branches, a folder that did not change, a commit that says so.
  • One project, one rule. The script is short and nobody else has to maintain it.
  • A monorepo where each project should build only when its own folders changed.

Examples for each are in the script guide and skip previews for bots and agents.

When turning auto-deploy off fits

  • You want one deploy when you decide, for example after the day's pushes, instead of one build per push.
  • Many projects. A rule per project is a lot of upkeep; one command covers all of them.
  • Coding agents push all day. Their pushes stop costing builds, and you see what is waiting before it goes live. Estimate the difference with the build cost calculator.

Steps: Disable Vercel auto-deploy. What changes on Vercel and Render: Auto-deploy off and on.

Using both

On Vercel the two do not stack. Once the Git connection is removed, a push starts no build, so there is nothing left for the step to skip. If you want previews on some branches, keep the Ignored Build Step and leave auto-deploy on for that project.

Questions

Can I keep preview builds and still deploy production by hand?

Yes, with an Ignored Build Step that skips production: exit 0 skips a build, so bash -c '[ "$VERCEL_ENV" = production ] && exit 0 || exit 1' builds previews and leaves production to you. With auto-deploy off in Deploy Center there is no Git connection on Vercel, so a push builds no preview; deploys vercel deploy <project> --preview builds one by hand.

Does a skipped build cost anything?

The Ignored Build Step runs after Vercel has created the deployment and cloned the repository, and it cancels the build before your build command runs. That is much cheaper than a build; your usage page shows how your plan counts it.

Which is less work for many projects?

An Ignored Build Step is set per project and a broken script builds instead of skipping. deploys vercel autodeploy-off --all turns auto-deploy off for every Vercel project at once.

Can I go back?

Yes. Remove the Ignored Build Step setting, or run deploys vercel autodeploy-on <project> to connect Git again from the repo Deploy Center wrote down.
