How long do failed deploys last? Recovery time

deploys recovery measures the time from a failed deploy to the next deploy of the same project. Failures in a row count as one outage. An outage with no later deploy is shown as open. It reads the journal only.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

deploys recovery                      # last 30 days
deploys recovery --days 90 --project web
deploys recovery --json

A made-up example:

Recovery over the last 30 days (time from a failure to the next deploy)
  2 outages, 1 recovered, 1 still open, typical recovery 3h 0m
    api (Render): 0 recovered, OPEN since 2026-11-22 02:04
    web (Vercel): 1 recovered, typical 3h 0m, longest 3h 0m

2. What counts as one outage

  • The clock starts at the first failure of a project.
  • More failures of the same project before it recovers belong to the same outage.
  • It ends at the next deploy of that project that went live.
  • No later deploy: the outage is open and is listed with its start.

Limit. The value is the time until the next deploy that Deploy Center saw, not until a user noticed or the site was back. If you fix a problem at your host without a deploy, the outage stays open.

3. What to do with it

  • A long typical time with few outages says that fixing is slow, not that breaking is common. A rollback is the fast way back, see roll back automatically.
  • An open outage is a failure nobody followed up. Look at it with deploys logs api and deploys history api.
  • Compare two months to see whether it gets better.

Every number comes from the journal on your Mac. No network, no platform call, nothing is started.

Questions

Is this the same as downtime?

No. A failed build usually leaves the old version live. The number says how long the project had a failure that nobody had deployed past yet.

Why is an outage still open?

Because no deploy of that project went live after the failure. Deploy again or roll back, or ignore it if the project is retired: deploys ignore api.

Does it use the network?

No. It reads the local journal.

How do I get one number for a report?

deploys recovery --json prints the typical recovery and the outages as JSON. deploys digest sums up the week.
