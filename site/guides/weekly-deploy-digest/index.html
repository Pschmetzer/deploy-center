A weekly digest of your deploys

deploys digest sums up the last 7 days from the journal: deploys, failures, rollbacks, forced starts, the busiest day, deploys per project and the latest failures. It adds an estimate of the build cost you saved. It starts nothing.

Last updated 23 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

deploys digest                    # last 7 days
deploys digest --days 30
deploys digest --no-savings       # skip the saving (no network)
deploys digest --json

A made-up example:

Digest of the last 7 days (2026-11-16 to 2026-11-23)
  2 deploys, 2 failed (50%), 1 rolled back, 1 forced
  Busiest day: 2026-11-21 (1)
  Projects:
    web (Vercel): 2 deploys, 1 failed
    api (Render): 0 deploys, 1 failed
  Latest failures:
    2026-11-22 02:04 api: Deploy failed
    2026-11-21 06:04 web: Build failed: exit 1

2. The saving is an estimate

The saving comes from deploys ledger: builds that did not run because auto-deploy is off, times an average build price. It is an estimate, not an invoice, and it needs the network. --no-savings leaves it out, and the rest then works offline. See how to save build minutes for the arithmetic.

3. Send it somewhere

The text is plain, so it fits a chat message or an email. Run it once a week from a scheduler of your choice and post the output:

deploys digest --no-savings > /tmp/digest.txt

The integrations send a daily summary to Slack, Discord, Telegram or ntfy on their own. The digest is the weekly view of the same journal.

4. How to read it

  • A failure rate above a few percent over many deploys is worth a look at deploys timeline.
  • Many forced starts mean the window is wrong for how you work.
  • A project with failures and no deploys is an open outage, see recovery time.

Questions

Does the digest start a deploy?

No. It reads the journal and prints. Nothing starts a build, a deploy or a rollback without a click or a command with --yes.

Why does it need the network?

Only for the saving, which asks the platforms what they would have built. With --no-savings it does not touch the network.

Can I get it as JSON?

Yes. deploys digest --json has the same numbers for a script.

What is the difference to the agent digest?

The agent digest is a different feature: once a day, what coding agents pushed. This one sums up your deploys from the journal.
