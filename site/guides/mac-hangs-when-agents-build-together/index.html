A build gate for Claude Code agents that hang your Mac

Put a gate in front of heavy commands. deploys perf gate -- npm run verify starts the command only when memory pressure, swapping and load leave room, and a Claude Code hook can do the same for every command an agent runs. Nothing is stopped; commands wait.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Running many Claude Code sessions on one Mac works until a dozen of them start tsc, vitest or next build at the same moment. Memory fills up, macOS starts swapping, and the whole Mac hangs, the sessions you are watching included. The cause is not one build but all of them at once.

1. See how full the Mac is

deploys perf status prints a level, the reasons and the biggest groups of processes (Claude Code sessions, MCP servers, checks and builds, dev servers, Xcode, Chrome, Docker). It is read-only.

deploys perf status
deploys perf status --json   # the same for scripts

Green means memory pressure is normal, nothing swaps and the load is under one per core. Yellow means busy. Red means overloaded: critical memory pressure, swap almost full and still growing, or a very high load.

2. Make heavy commands wait

The gate holds a command until there is room, then runs it:

deploys perf gate --max-wait 10m -- npm run verify

A command starts when memory pressure is normal (or at "warn" with little swapping), the load is under 1 per core (now and over five minutes), fewer heavy checks run than the cap, and the last start through the gate was at least 20 seconds ago, so the new process shows up before the next one starts. After --max-wait a yellow Mac starts the command anyway; a red one does not (exit code 75) unless you add --fail-open. If the guard itself fails, the command runs.

3. Let Claude Code use the gate

A PreToolUse hook for the Bash tool recognises heavy commands such as tsc, vitest, eslint, next build, npm run verify or docker build, and lets light ones through at once. A heavy one waits for room; when the Mac stays red, the command is not started and Claude is told to wait or to use a cloud session.

deploys perf hook    # prints the entry for ~/.claude/settings.json; nothing is changed

Copy perf-gate.sh from the plugin's hooks folder to ~/.claude/hooks/ and add the printed entry under hooks.PreToolUse. DEPLOYS_PERF_GATE=0 turns the hook off for one session.

Trade-offs. A gate makes the second and third build slower, on purpose. It never stops a live session, and it does not make one build faster. If a Mac is red all day, run fewer sessions or move some to the cloud.

In the Mac app

Deploy Center shows the same level as a green, yellow or red dot in the menu bar and next to the build costs; a click opens the reason and the biggest consumers.

Questions

Does the gate stop my agents?

No. It holds a heavy command until there is room and then starts it. It never stops a running session.

What is a heavy command?

A test, type check, lint, build or Docker build such as tsc, vitest, eslint, next build, npm run verify or docker build, run as a command of its own. grep tsc is not heavy.

What if the Mac stays overloaded?

After the wait a yellow Mac starts the command anyway. A red Mac does not: the command exits with code 75, unless you pass --fail-open.

Does it need a server or an account?

No. It reads the kernel's memory pressure, swap and load on your own Mac.
