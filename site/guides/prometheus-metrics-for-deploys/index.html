Deploy metrics in Grafana, without a server

deploys metrics prints, in Prometheus text format, how many commits wait per project, how old the oldest is, whether the newest deploy failed and whether a push still builds by itself. With --out it writes a file that node_exporter's textfile collector reads. No server of ours is involved.

Last updated 23 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

deploys metrics                                  # print the text
deploys metrics --out /var/lib/node_exporter/deploys.prom

The file is written to a temporary name and moved into place, so a scraper never reads half a file. It is readable by other accounts (mode 644), because node_exporter usually runs as another user.

2. What it writes

Per project, with the labels platform and project:

  • deploycenter_waiting_commits: commits on the branch that are not live yet.
  • deploycenter_oldest_waiting_seconds: age of the oldest of them.
  • deploycenter_auto_deploy: 1 when a push builds by itself.
  • deploycenter_building: 1 while a deploy is running or queued.
  • deploycenter_failed: 1 when the newest deploy failed.

And for the whole run: deploycenter_up (0 when a platform did not answer, then the numbers may be short), deploycenter_scrape_timestamp_seconds and deploycenter_projects per platform. The exit code is 1 when a platform did not answer.

3. Run it on a schedule

Run the command from cron or launchd every few minutes and let node_exporter read the folder with --collector.textfile.directory:

*/5 * * * * deploys metrics --out /var/lib/node_exporter/deploys.prom

Use deploycenter_scrape_timestamp_seconds to alert when the file is stale. Names of projects are labels, so use made-up names in public dashboards and screenshots.

4. Alerts worth having

  • deploycenter_failed == 1 for 30 minutes: the newest deploy of a project failed and nobody fixed it.
  • deploycenter_oldest_waiting_seconds > 3 * 86400: a change has waited three days.
  • deploycenter_auto_deploy == 1: a push builds by itself again. The guard in the app turns it off, see stop building every push.

Questions

Does it start a deploy or write to the platforms?

No. It reads the state of the projects and prints text. Nothing starts a build, a deploy or a rollback without a click or a command with --yes.

Does it need a Prometheus server?

Only to scrape the file. The CLI itself needs none. The textfile collector of node_exporter reads the folder.

What does deploycenter_up 0 mean?

A platform did not answer, so the numbers can be short. Do not read a missing project as a healthy one.

Does it send my data anywhere?

No. The file stays where you write it.
