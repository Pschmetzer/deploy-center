Set up a status page for your deploys

Copy statuspage.example.json to statuspage.json, list the projects to show, and run integrations/statuspage/statuspage.sh. It writes index.html, feed.xml and status.json into public/ and deploys nothing: you upload the folder to any static host.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. What you get

Three files, no server and no external assets:

FileWhat is in it
index.htmlOne page, light and dark, readable on a phone.
feed.xmlAn Atom feed with one entry per deploy in the timeline.
status.jsonThe same data for other tools, with schema: 1.

For each project the page shows the state and time of the live deploy (Live, Deploying, Failed), what is merged but not live yet ("Coming next"), an optional site check, and below that the recent deploys from the app's journal.

2. Write the config

{
  "title": "Acme deploys",
  "description": "What shipped when.",
  "baseUrl": "https://status.example.com/",
  "projects": [
    "app-web",
    "render/worker",
    { "name": "api", "platform": "render", "label": "API", "url": "https://api.example.com/health" }
  ],
  "hideMessages": true,
  "showAuthors": false,
  "timeline": 30
}

projects is an allowlist: only these are shown, in this order, and without it the script stops and writes nothing. hideMessages: true shows "Updated" instead of commit messages, in the page, the feed and status.json.

3. Generate the page

cp integrations/statuspage/statuspage.example.json statuspage.json   # then edit it
integrations/statuspage/statuspage.sh                  # reads ./statuspage.json, writes ./public/

Open public/index.html locally first. Then upload public/ to any static host: S3, Cloudflare Pages, a web server with rsync -a public/ host:/var/www/status/, or drag the folder onto Netlify Drop. Nothing runs on the server.

4. Before anyone outside sees it

  • Set "strict": true for a page anyone may see. It implies hideMessages, moves the page's script into status.js so a script-src 'self' policy holds, and adds noindex.
  • Never published: projects that are not in the list, repositories, commit SHAs, error texts and the URLs of site checks.
  • The site check fetches the address once while the page is made. It is the result at that moment, not uptime over time.

5. Keep it fresh

The page is a snapshot. Run the script from launchd or cron and upload afterwards. If the job stops, staleHours (default 48) puts a red line on the page that says how old it is.

Questions

Does the status page deploy anything?

No. The script only writes three files. You decide where they go.

Does it show commit messages?

Not if hideMessages is on, which the example config sets. With strict it is on by itself.

Is it an uptime monitor?

No. The optional site check is one request when the page is made. For uptime over time you need a monitor that polls the site.

Can other tools read it?

Yes. status.json has the same data and a schema number, so a tool can tell when the format changes.
