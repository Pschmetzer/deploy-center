Your deploy queue: what is merged but not live

With auto-deploy off, your deploy queue is whatever is merged but not live. deploys changed lists it per project, deploys plan adds an estimate per build, and deploys deploy-changed --yes starts it. Nothing starts without --yes or a click.

Last updated 20 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Two queues, not one

The word covers two different things:

  • The host's build queue: builds waiting for a free build slot at Vercel, Netlify, Render or Cloudflare. How many run at once depends on your plan. See build minutes and the build queue and, for the monthly build limit on Cloudflare Pages, that guide.
  • Your queue of changes: commits and pull requests merged on GitHub that no deploy has shipped yet. This is the one you can control, and the one Deploy Center shows.

2. See what is waiting

deploys changed                 # commits and PRs per project that are merged and not live
deploys explain web             # why a project is, or is not, counted as changed
deploys diff web                # the commits and files between what is live and the branch
deploys notes web               # the same as release notes (Markdown)

deploys plan prints the same list with an estimate per build and the sum. It starts nothing:

deploys plan --when-green --since 1d

3. Start it on purpose

deploys deploy-changed              # shows the list, starts nothing
deploys deploy-changed --yes        # starts one deploy per project with changes
deploys deploy-changed --when-green --yes   # only commits whose CI passed

Several projects do not all start at once. The setting Builds at the same time defaults to 2: deploying ten projects starts two builds, then the next two. The setting is in Settings, see the settings reference.

4. Watch and cancel

deploys status                  # what is building now, and what failed last
deploys watch web --timeout 30m # follow the newest deploy until live or failed
deploys cancel web              # stop a build that is running, on whichever host

In the app, stopping a deploy that is still queued lets the next one start and counts it as cancelled in the summary of the run.

Limit. cancel stops a build that Deploy Center can see running. A build another tool or a Git push started shows up in deploys triggers, and you stop it at your host.

Questions

Does deploy-changed start a deploy by itself?

No. Without --yes it only shows the list. Nothing starts a build, a deploy or a rollback without a click or a command with --yes.

Why is a project not in the list?

Run deploys explain <project>. It says why a project is or is not counted as changed, for example because it was ignored with deploys ignore.

Can I keep a project out of the queue?

Yes. deploys ignore my-project leaves it out of changed and deploy-changed.

Is this the same as my host's build queue?

No. The host's queue holds builds that were already started. Deploy Center's list holds changes that have not been started yet, so you decide when they enter the host's queue.

Use Vercel or Render too?

Deploy Center turns off auto-deploy on Vercel and Render in one click, Netlify and other hosts opt-in, and deploys what changed when you decide. Free and open source for macOS.
