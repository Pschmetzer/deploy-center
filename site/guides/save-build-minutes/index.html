How to save build minutes on any host

Build minutes are the number of builds multiplied by how long each takes. Cut the number first: skip pushes nobody needs live, skip projects a commit did not touch, and let one deploy cover many commits. Only then make a single build faster.

Last updated 20 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Count what builds

Every push to a connected repository starts a build for every project connected to it, on every branch. So the count is pushes times projects, not releases.

builds = pushes x projects connected to the repository

Your host's usage page shows what it really billed. From a terminal, Deploy Center reads the same data where the host reports it:

deploys costs 14        # Vercel: charges per day for the last 14 days
deploys history web 20  # the last 20 deploys of one project
deploys triggers        # builds nobody started from here in the last 24 hours

2. Cut builds, biggest first

  1. Bots and agents. Dependabot, Renovate and coding agents push to their own branches. Skip their previews: Vercel, Netlify, Cloudflare Pages and Render.
  2. Projects a commit did not touch. In a monorepo one push builds every project. See monorepo ignore rules.
  3. Production on your schedule. Turn off auto-deploy and deploy once when the work is done: Vercel, Render, Netlify, Cloudflare Pages.
  4. Commits that need no build. A README or comment change does not need a deploy. Render has build filters and [skip render] in a commit message; on Vercel an Ignored Build Step can read the commit message.

3. Then shorten the builds that remain

  • Keep tests and lint in CI, not in the build command, unless the build needs them.
  • Install only the dependencies the build needs; in a monorepo, build the one app, not the workspace.
  • Use your host's dependency cache. What each host caches differs, so read its build documentation instead of assuming.
  • Find the slow step in the build log first. deploys logs web prints the end of the newest build log with keys and tokens masked.

Trade-offs. Fewer builds means fewer preview links and a fix that is not live until you deploy it. Keep previews where people review, and skip them where nobody looks.

4. Check what you saved

Deploy Center estimates the effect and labels the numbers as estimates:

deploys simulate --days 30   # auto-deploy for a month against one deploy a day
deploys ledger               # builds and money saved since auto-deploy was turned off
deploys price set vercel 0.008   # your price of one build minute, where no billing says it

The build cost calculator does the same sum in the browser with your own numbers.

Questions

Is it cheaper to have fewer builds or faster builds?

Fewer. A build that never starts costs nothing, while a faster build still runs once per push. Do both, in that order.

Does a skipped build cost anything?

A skipped build is cancelled before your build command runs, so it is much cheaper than a full build. Check your host's usage page to see how your plan counts it.

Do these tips work on every host?

The counting and the order do. The settings differ per host, so the steps link to one guide per host.

Where do I see my real numbers?

On your host's usage or billing page. deploys costs shows Vercel's charges per day, and deploys simulate estimates the rest from your own deploy history.
