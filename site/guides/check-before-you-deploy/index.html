Check what a deploy would ship: risk, diff and secrets

Before a deploy, run deploys risk <project> for a green, yellow or red score of the waiting diff, deploys secrets <project> to find added lines that look like a key, and deploys diff <project> to read what changes.

Last updated 20 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Read what changes

deploys changed         # commits and PRs waiting, per project
deploys diff web        # the commits and files between what is live and the branch
deploys notes web       # the same as release notes (Markdown)

2. The risk score

deploys risk web --json

It scores the diff between what is live and the branch (from GitHub's comparison, at most 300 files). The worst finding sets the level:

FoundLevel
migrations: migrations/, migrate/, prisma/, *.sql, schema.prisma, schema.rbred
lockfiles such as package-lock.json, pnpm-lock.yaml, yarn.lock, Cargo.lock, go.sumyellow
.env and .env.*yellow
config such as vercel.json, render.yaml, Dockerfile, .github/workflows/yellow
more than 500 changed lines or 30 filesyellow
more than 3000 changed lines or at least 100 filesred

deploy-changed without --yes names a red risk next to the project. In the app a row shows a red dot only for red; yellow stays quiet, and the details list every reason.

3. Look for secrets in what waits

deploys secrets web && deploys deploy web --yes     # a gate in a script
git diff A..B | deploys secrets --stdin             # a diff you pipe in

It looks only at the lines that were added in what waits to go live, with the same patterns that mask logs (keys, tokens, private keys). It prints file names and the masked line, never the secret, and exits 1 when it finds one. It needs perl.

Not a full scanner. deploys secrets is a quick gate. For gitleaks, OSV-Scanner and Semgrep on a fresh copy of the repository, use deploys check start owner/repo, see the scan docs.

4. Put the checks in front of the deploy

deploys plan --when-green        # the list with an estimate per build, nothing starts
deploys risk web && deploys secrets web && deploys deploy web --yes

A red risk is information, not a block: you read the reasons and decide. Combine it with CI that must be green and a rollback check.

Questions

Does a red risk stop the deploy?

No. It names a risk and the reasons. You decide, and deploy-changed without --yes shows it next to the project.

Which files make a diff red?

Migrations, a diff of more than 3000 lines or at least 100 files. Lockfiles, .env files, host config and a diff over 500 lines or 30 files make it yellow.

Does secrets send my code anywhere?

No. It reads the diff on your machine with the patterns that mask logs, and prints only file names and the masked line.

Does it work for GitLab?

Pipe a diff into deploys secrets --stdin.
