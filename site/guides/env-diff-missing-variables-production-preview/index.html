Compare production and preview variables

Run deploys env-diff <project>. It lists the variable names that exist in production but not in preview, and the other way round. Values are never read into the output, so the result is safe to paste into a ticket.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

A preview build that fails with "undefined" or a missing key is often a variable that someone added for production only. Finding it in a dashboard means opening two lists side by side. deploys env-diff does the comparison and prints only names.

1. Compare

deploys env-diff example-web
deploys env-diff example-web --json

Example output (made-up names):

Environment variable names of example-web (values are never read here)
  production: 12, preview: 10, in both: 10
  Only in production (a preview build may miss them):
    - STRIPE_WEBHOOK_SECRET
    - SENTRY_AUTH_TOKEN

2. Decide per variable

Not every difference is a bug. A production-only secret for a live webhook should not exist in preview. A variable that the build needs, such as a public API URL, should. Add the second kind to the preview environment in the host's settings. Deploy Center reads names; it does not copy values between environments.

3. Use it in a check

The command exits with 1 when the names differ and 0 when they match, so a script can stop before a deploy:

deploys env-diff example-web --json >/dev/null || echo "variables differ between production and preview"

Trade-offs. Only Vercel exposes a production and preview split here. For other hosts the command says there is nothing to compare. It compares names, so it cannot tell that two values differ.

Questions

Does it print secret values?

No. Only the names and the environments they belong to are read; values never leave the provider function and are not printed, logged or journaled.

Which hosts does it work with?

Vercel. A host without a production and preview split, or without an API for it, says so and exits normally.

Can I use it from Claude?

Yes. The MCP server has a read-only deploys_env_diff tool that returns the same names.

What does the exit code mean?

0 when production and preview have the same names, 1 when they differ.
