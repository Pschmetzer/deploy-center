Set up a deploy freeze for Friday afternoon

Create ~/.config/deploys/window.json with a deny rule such as {"days": ["fri"], "from": "15:00"}. Inside that window deploys deploy and deploy-changed --yes refuse to start production deploys, unless you pass --force "reason".

Last updated 27 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Write the window

The file is ~/.config/deploys/window.json (or $DEPLOYS_CONFIG/window.json). Each entry in deny is a time when production deploys are not allowed:

{
  "deny": [
    { "days": ["fri"], "from": "15:00" },
    { "days": ["sat", "sun"] },
    { "from": "22:00", "to": "06:00", "reason": "nobody is awake to fix it" },
    { "dates": ["2026-12-24", "2026-12-31"] }
  ]
}
  • days: mon to sun. Leave it out for every day.
  • dates: YYYY-MM-DD, for holidays.
  • from and to: local time, HH:MM. They default to 00:00 and 24:00. If from is later than to, the rule runs over midnight.
  • reason: the text shown. Without it the rule is described, for example fri 15:00-24:00.

2. Ask whether it is open

deploys window          # Open or Closed, and which rule
deploys window --json   # {"denied":true,"reason":"fri 15:00-24:00",...}

deploys window exits 1 while the window is closed, so a script can stop on it. With --json it always exits 0.

3. What it blocks, and what it does not

Inside a closed window these refuse to start production deploys: deploys deploy, deploys deploy-changed --yes, deploys vercel deploy, deploys render deploy, and the deploy command the app uses.

These still go out, because they are fixes or harmless: previews (--preview), rollbacks, and verify.

What it cannot stop. The window guards deploys started with Deploy Center. A push that your host deploys by itself is not stopped by it. Turn auto-deploy off, and let the guard turn it off again if it comes back, so every production deploy goes through the window.

4. Let a hotfix through

deploys deploy-changed --yes --force "hotfix for the login page"

Every project started this way gets a forced entry in the deploy history, with the window and your reason. In the app, the confirmation asks first if the window is closed; Deploy anyway… takes the reason. Settings → Deploy → Deploy window edits the same file.

5. A script instead of a file

For a rule that a time table cannot say, a pre-deploy script in ~/.config/deploys/hooks.d stops a start with a non-zero exit:

#!/bin/sh
# no deploys on Friday afternoon
[ "$(date +%u%H)" -lt 515 ] || { echo "no deploys on Friday afternoon" >&2; exit 1; }

Make it executable with chmod 700. Hooks are read from your own config folder only, never from a repository.

Questions

Does the freeze stop a rollback?

No. Rollbacks, previews and verify go out inside a window, because a rollback is a fix.

How do I deploy a hotfix during the freeze?

Pass --force with a reason, or use Deploy anyway… in the app. The reason goes to the deploy history.

Does a push still deploy if auto-deploy is on at the host?

Yes. The window only guards deploys started with Deploy Center. Turn auto-deploy off at the host so that production deploys go through it.

Which time zone does the window use?

Local time of the Mac or machine that runs the command, as from and to are local times.
