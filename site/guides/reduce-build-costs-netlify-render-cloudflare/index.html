Reduce build costs on Netlify, Render and Cloudflare Pages

The levers are the same on every host: fewer builds, then cheaper builds. Netlify: Stop builds or an ignore command. Render: Auto-Deploy Off, After CI Checks Pass, Build Filters. Cloudflare Pages: turn off production and preview deployments, which also saves your monthly build limit.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. What this guide counts

Prices and plan limits change, so this guide counts builds, not dollars. Look at your host's usage or billing page for what a build costs you, and use deploys simulate or the build cost calculator to estimate the saving with your own numbers.

2. Netlify

  • Stop builds turns off every build, build hooks included; you deploy by uploading a build with the CLI.
  • An ignore command in netlify.toml cancels builds it rejects. test -z "$INCOMING_HOOK_TITLE" skips everything except builds started by a build hook.
  • Previews for bots can be skipped with a script: skip preview builds for bots.

Details and trade-offs: Stop Netlify builds.

3. Render

  • Auto-Deploy has three settings: On Commit, After CI Checks Pass, and Off. After CI Checks Pass skips deploys of pushes whose checks fail.
  • Build Filters (included and ignored paths) keep a README change from deploying.
  • [skip render] in a commit message skips that commit.
  • Pull request previews are a separate setting.

Details: Turn off Render auto-deploy.

4. Cloudflare Pages

Cloudflare does not charge per build. Pages plans have a build count limit, and every push to a connected repository, and every push to a preview branch, uses one build. Set Production deployments and Preview deployments to off to stop push builds, and check with one real build how a deployment you create by hand behaves. Details: Stop Cloudflare Pages builds.

5. On every host

  1. Turn off push builds for production and deploy once when you are ready: deploys netlify autodeploy-off <site>, deploys render autodeploy-off --all, deploys cloudflare off <project>.
  2. Deploy what changed with deploys deploy-changed --yes, or on a schedule with a daily deploy.
  3. Set a spending line with deploys budget set 50 --strict: deploy-changed --yes then stops before going over it.
  4. Read the result with deploys ledger.

Trade-offs. With push builds off, a merged fix is not live until someone deploys it. Keep a deploy freeze and a rollback check in place so that deploying less often stays safe.

Questions

Which host is cheapest?

That depends on your plan, your builds and your traffic, and it changes. This guide does not rank hosts; it lists the settings that cut builds on each.

Does Cloudflare Pages charge per build?

No. Pages plans have a build count limit per month instead. Each push to a connected repository and each preview branch push uses one build.

Does Deploy Center support all three?

Yes. Netlify and Cloudflare Pages are opt-in hosts (deploys providers enable netlify, deploys providers enable cloudflare), and Render is on by default.

Where do I see what I saved?

deploys ledger estimates builds and money saved since auto-deploy was turned off. It is an estimate, not an invoice.

Use Vercel or Render too?

Deploy Center turns off auto-deploy on Vercel and Render in one click, Netlify and other hosts opt-in, and deploys what changed when you decide. Free and open source for macOS.
