Check your setup: tools, logins and keys

deploys doctor --text checks the tools and logins Deploy Center needs and prints one line each: ok, off or FIX, with the command that fixes it. deploys creds adds where each platform's key comes from, whether it works and how old it is. Both only read.

Last updated 23 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run doctor

deploys doctor --text
deploys doctor --text --strict     # exit 1 when a line says FIX
deploys doctor --fix               # the commands to type, nothing is run
deploys doctor                     # the same facts as JSON

An example from a fresh machine:

ok   jq
ok   gh (GitHub CLI)
FIX  gh is logged in   -> gh auth login
ok   curl
ok   the settings folder is writable
     bash 5.2.21, jq 1.7
     render: {"renderKey":false,"renderKeySource":"none"}
     vercel: {"vercelCli":false,"vercelApi":false,"vercelLoggedIn":false}
off  secret-tool is missing: the keychain (keys fall back to the environment) does not work

2. How to read it

  • ok: it works.
  • off: an optional piece is missing. Deploy Center works without it, with a fallback that the line names.
  • FIX: something you need is not set up, and the line ends with the command that fixes it.
  • The unmarked lines are facts: versions and what each platform answered.

deploys doctor --fix lists the same problems as numbered suggestions. It shows commands for you to type. It never runs them.

3. Check the keys

deploys creds                  # where each key comes from, if it works, how old
deploys creds --max-age 90 --json

It prints one row per platform:

PLATFORM  KEY FROM  STATE         KEY AGE  NOTE
Render    missing   NOT accepted  -
Vercel    login     NOT accepted  -

The key comes from the environment, the keychain or a login. A key in the keychain also shows its age, and one older than --max-age days is flagged so you rotate it. The command never prints a key.

4. Run it where it helps

  • After installing on a new Mac, a CI runner or a server: deploys doctor --text --strict as the last step of the setup.
  • Before a scheduled deploy: a failed login shows up here instead of at 09:00. See deploy once a day.
  • When a deploy says "unauthorized": run creds first. Most of the time a key expired or moved.

Questions

Does deploys doctor change anything?

No. It checks and prints. Nothing starts a build, a deploy or a rollback without a click or a command with --yes, and --fix only shows commands.

What is the difference between doctor and creds?

doctor checks tools and logins. creds is about the platform keys: where each comes from, if it is accepted and how old it is.

Is a key ever printed?

No. Neither command shows a key, and keys never go on a command line or into the journal.

Can I use it in CI?

Yes. deploys doctor --text --strict exits 1 when a line says FIX.
