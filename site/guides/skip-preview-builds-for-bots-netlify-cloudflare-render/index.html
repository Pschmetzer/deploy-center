Skip preview builds for bots on Netlify, Cloudflare and Render

On Netlify add an ignore script that exits 0 for bot branches. On Cloudflare Pages restrict the preview branches or turn previews off. On Render a service builds only the branch it is set to, so bot branches matter only through pull request previews, which have their own setting.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Know the branch names

Bots and agents use predictable branch prefixes: dependabot/… for Dependabot, renovate/… for Renovate, and for coding agents whatever prefix the tool uses, such as claude/… or cursor/…. Check the branches in your own repository, then use those prefixes in the rules below. For Vercel see the Vercel guide.

2. Netlify: an ignore script

Netlify runs the ignore command before each build: exit 0 cancels the build, exit 1 builds. It sets BRANCH to the branch being built.

# netlify.toml
[build]
  ignore = "bash scripts/netlify-ignore.sh"
#!/usr/bin/env bash
# scripts/netlify-ignore.sh  -  exit 0 = skip the build, exit 1 = build
case "$BRANCH" in
  dependabot/*|renovate/*|claude/*|cursor/*) exit 0 ;;
esac
exit 1

Test it locally with BRANCH=renovate/x bash scripts/netlify-ignore.sh; echo $?, which should print 0. The cancelled builds still show in the deploy list. If you also use the build-hook rule from the Netlify guide, put both checks in one script, because Netlify reads one ignore command.

3. Cloudflare Pages: limit the preview branches

In the Pages project open Settings → Builds & deployments and look at Preview deployments. If your dashboard offers a choice of branches, include only the branches people use or exclude the bot prefixes. If it only offers all or none, set it to none and open previews by hand. Cloudflare counts every build against a monthly build limit, so skipped previews also leave room for the builds that matter. Details are in the Cloudflare Pages guide.

4. Render: previews have their own setting

A Render service deploys the branch it is configured for, so a push to a bot branch does not build it. Builds come from pull request previews, which are a separate setting per service, from auto-deploy of the service's own branch, and from the bot's pull requests merging into it. Turn pull request previews off or to manual where nobody reviews them, and use Build Filters or [skip render] for commits that need no build. See the Render guide.

Trade-offs. A bot pull request without a preview has to be reviewed from its diff and CI. If a dependency update is risky, build it by hand: that is one deploy you chose, not one per push.

5. See what a push would build

deploys hooks install puts a Git pre-push hook into a repository. Before each push it shows which Vercel and Render builds the push would start, so you notice a bot branch building before it does.

Questions

Which branch prefixes do bots use?

Dependabot uses dependabot/ and Renovate uses renovate/ by default. Coding agents use their own prefix, so look at the branches they created in your repository.

Does a skipped Netlify build still appear?

Yes. Netlify cancels it, and it shows in the deploy list as a cancelled deploy.

Will the production branch be affected?

Only if your rule matches it. The prefixes above never match main. If you also want production on your schedule, turn auto-deploy off instead.

Can I keep previews for pull requests people open?

Yes. The rules match branch names, so a pull request from a branch without a bot prefix still gets its preview.
