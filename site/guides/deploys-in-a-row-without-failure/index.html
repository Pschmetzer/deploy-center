Deploys in a row without a failure: your streak

deploys streak counts, per project, how many deploys in a row went live without a failure: the streak now and the longest one. It also shows the number of deploys, failures and the date of the last failure. It reads the journal only.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

deploys streak                       # last 90 days
deploys streak --days 30 --project web
deploys streak --json

A made-up example:

Deploys in a row without a failure, last 90 days
  web (Vercel): 2 now, longest 2 (2 deploys, 1 failed, last failure 2026-11-21)
  api (Render): 0 now, longest 0 (0 deploys, 1 failed, last failure 2026-11-22)

2. How it counts

  • now: deploys since the last failure of that project. A failure sets it back to 0.
  • longest: the best run inside the period.
  • A project with a failure and no deploy after it, like api above, shows 0.

A long streak is only as good as the deploys behind it. Three deploys in a row is a small number, 40 is not.

3. Use it

  • As a quick health check on Monday: which project broke last?
  • As a number for a README, a status page or a report. --json has it per project, see the status page guide.
  • Next to recovery time: how often it breaks, and how long it takes to fix.

Every number comes from the journal on your Mac. No network, no platform call, nothing is started.

Questions

What counts as a failure?

A deploy that ended in the result failed in the journal. A rollback or a forced start is not a failure by itself.

Why is the streak 0 for a project that works?

Its last journal entry in the period is a failure, or there is no deploy after the last failure. Deploy again and it counts.

Does a longer period change the result?

Yes. --days 365 looks back further, so the longest streak can be bigger. The streak now stays the same.

Does it work without the network?

Yes. It reads the local journal.
