Find projects that nobody deploys

deploys idle lists the projects with no deploy for a number of days (default 90), on every platform that is on. They are candidates to pause or delete. The command reads only and changes nothing.

Last updated 23 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

deploys idle                 # no deploy for 90 days
deploys idle --days 180
deploys idle --json

The result is sorted, and the list is empty when every project had a deploy in the period. --days 0 is refused.

2. Why it matters

  • An idle project can still cost something: a paid instance, a database, a domain, a cron job or a preview that keeps rebuilding.
  • It still has a key, a webhook and a Git connection that someone has to keep safe.
  • It is noise in deploys list and in the menu bar count.

3. What to do next

  1. Open the project to see what it is, with deploys open <project> --dashboard.
  2. If it is used, leave it. If it is retired, pause or delete it at your host. Deploy Center does not delete projects.
  3. Keep a live project that you simply do not deploy out of the queue, with deploys ignore <project>.

Limit. A project that serves traffic but is not redeployed is idle in this sense, so "idle" is not "unused". The list is a prompt to look, not a verdict.

Questions

Does it pause or delete anything?

No. It lists. Nothing starts a build, a deploy or a rollback without a click or a command with --yes.

What counts as a deploy?

The newest deploy the platform reports for the project. A project with no deploy in the period is listed.

Is a static site that never changes idle?

It shows up in the list. That is fine. Leave it or ignore it.

Can I use it in a script?

Yes. deploys idle --json prints a list.
