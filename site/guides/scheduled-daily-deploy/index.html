Deploy once a day on a schedule

Run deploys schedule daily 09:00 --when-green on your Mac. It sets up a job (launchd, or a cron line) that runs deploy-changed --yes once a day. Without a Mac, a GitHub Actions workflow does the same from a runner.

Last updated 26 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Look before you schedule

deploys changed                       # what would go live
deploys deploy-changed --when-green   # the list, with CI verdicts; starts nothing

Run these a few days by hand. If the list is what you expect, schedule it.

2. On your Mac

deploys schedule daily 09:00 --when-green   # once a day at 09:00, only green commits
deploys schedule status                     # is it set up, and with which arguments
deploys schedule off                        # remove it

The job runs deploys deploy-changed --yes with the options you gave, through launchd, or prints the cron line. The same rules apply as for a deploy by hand: the deploy window can refuse it, your pre-deploy and post-deploy hooks run around it, and a budget set with deploys budget set stops it before going over.

The job lives on that Mac. For a schedule that does not depend on one machine, use a workflow.

3. From GitHub Actions

The repository's examples/daily-deploy.yml runs every weekday and deploys everything with commits that are not live. Started by hand it only shows the list. It needs gh logged in through GH_TOKEN, your host's token (for example VERCEL_TOKEN or RENDER_API_KEY) and the CLI release tarball. Run it once by hand and read the log before you trust it. See Deploy from CI and the GitHub Actions guide.

Scheduled workflows stop after 60 days. GitHub switches a schedule: workflow off when the repository has had no activity for 60 days. A repository that nobody pushes to is exactly that, so the workflow tells you when it fails and you should check it now and then.

4. Keep a daily deploy safe

  1. Add --when-green, so a red commit waits for tomorrow: deploy only when CI is green.
  2. Add a health check that rolls back: automatic rollback.
  3. Turn off auto-deploy on the host, or pushes deploy on their own as well. deploys triggers lists builds nobody started from here.

Questions

Does Deploy Center deploy on a schedule by default?

No. It deploys when you press Deploy or run a deploys command. The daily reminder in Settings is only a notification, and only when something waits. A scheduled deploy is something you set up yourself.

Can I deploy only on weekdays?

A deploy window can deny weekends, see the freeze guide. The GitHub Actions example runs on weekdays.

What happens if a deploy is refused by the window?

The job does not start production deploys inside a closed window, unless it was given --force with a reason.

How do I stop it?

deploys schedule off removes the job.
