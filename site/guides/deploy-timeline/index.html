A deploy timeline: what happened, day by day

deploys timeline prints what happened to your deploys, newest day first: deploys, failures, rollbacks and forced starts, each with time, project and platform. It reads the local journal only. It needs no network and starts nothing.

Last updated 23 November 2026 · by Patrick Schmetzer, author of Deploy Center

Deutsche Fassung

1. Run it

Without options it shows the last 3 days:

deploys timeline
deploys timeline --days 7 --project web --limit 20
deploys timeline --json

A made-up example (times are UTC):

Timeline of the last 3 days (UTC)
  2026-11-23
    05:04  forced   web (Vercel): Deployed in the window "Friday": hotfix
    04:04  rollback web (Vercel): back
  2026-11-22
    04:04  deploy   web (Vercel): ok
    02:04  FAILED   api (Render): Deploy failed

2. Read the lines

  • deploy: a deploy that went live.
  • FAILED: a build or deploy that failed, with the shortened error text. Keys and tokens are masked before they reach the journal.
  • rollback: production was moved back to the deploy before.
  • forced: a deploy started inside a closed window with --force "reason". The reason is in the line, see the freeze guide.

Only what Deploy Center started or recorded is in the journal. A push that your host built by itself does not appear. That is the reason to turn auto-deploy off.

3. Add your own line

A note goes into the journal and shows up in the timeline, which helps when you look at it a month later:

deploys note web "switched the image CDN"

A note has at most 200 characters. A text that looks like a key or token is refused. The command touches no platform.

4. Use it

  • After an incident: what was deployed in the hours before it, and was there a rollback?
  • On Monday: what changed on Friday while you were away?
  • In a script: deploys timeline --json for a chat message or a ticket.

Every number comes from the journal on your Mac. No network, no platform call, nothing is started.

Questions

Does deploys timeline start or change anything?

No. It reads the journal and prints. Nothing starts a build, a deploy or a rollback without a click or a command with --yes.

Which time zone does it use?

UTC, for the day headings and the times. Take the offset to your own zone into account when you read an incident.

Why is a deploy from my host's dashboard missing?

The journal holds what Deploy Center started or recorded. A build that a Git push or another tool started is not written there. deploys triggers shows such builds.

Can I look at one project only?

Yes. --project web filters by name, --days sets how far back it looks and --limit caps the number of lines (default 50).
