How to turn off Auto Deploy in Coolify and stop build storms

Open the application in Coolify and turn Auto Deploy off in its settings, or set is_auto_deploy_enabled to false through the API. Coolify then ignores push webhooks for that application, and you deploy when you decide.

Last updated 16 November 2026 · by Patrick Schmetzer, author of Deploy Center

On Vercel or Netlify, too many builds show up on a bill. On Coolify they show up on your own server: it builds on the machine that runs your apps unless you set up a separate build server. Five quick pushes are five builds back to back, and only the last was ever going to stay live.

1. Turn Auto Deploy off

In the application's settings, switch Auto Deploy off. Through the API, the field is is_auto_deploy_enabled (API access has to be on under Settings, Advanced, and the token needs the write permission):

curl -s -X PATCH "$COOLIFY_URL/api/v1/applications/$APP_UUID" \
  -H "Authorization: Bearer $COOLIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"is_auto_deploy_enabled": false}'

Pull request preview deployments are a separate setting; turn them off too if they are on.

2. Deploy when you choose

curl -s -X POST "$COOLIFY_URL/api/v1/deploy?uuid=$APP_UUID" \
  -H "Authorization: Bearer $COOLIFY_TOKEN"

The token needs the deploy permission. Coolify builds the newest commit of the branch.

Trade-offs. Nothing builds from a push any more, so a forgotten deploy means the old version keeps running. A token limited to some projects cannot list applications; give it team-wide scope.

Coolify in Deploy Center

Deploy Center supports Coolify as an opt-in host: deploys providers enable coolify, deploys coolify set-url https://coolify.example.com, pbpaste | deploys coolify set-key. deploys coolify autodeploy-off <app> sets the field, reads it back, and keeps the old value so autodeploy-on can restore it. Rollback needs Coolify v4.3 or newer. Details: the Coolify provider docs.

Questions

Why do builds hurt more on Coolify?

They run on your own server, by default the same one that runs your apps. A burst of pushes queues a burst of docker builds and slows every app on it.

Which field turns Auto Deploy off?

is_auto_deploy_enabled on the application, set to false with PATCH /api/v1/applications/{uuid}, or the Auto Deploy switch in the application settings.

Do preview deployments stop too?

No. Pull request preview deployments are a separate setting.

Does Deploy Center support Coolify?

Yes, as an opt-in host. It sets the field, reads it back and can restore the previous value.
