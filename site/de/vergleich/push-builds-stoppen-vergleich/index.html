Push-Builds stoppen: Vercel, Netlify, Render, Cloudflare im Vergleich

Jeder Anbieter hat einen Schalter, und sie unterscheiden sich darin, was sie stoppen. Vercel kann Git trennen oder per Regel überspringen, Netlify hat Stop builds oder einen ignore-Befehl, Render hat Auto-Deploy Off, und Cloudflare Pages hat zwei Schalter, einen für Production und einen für Previews.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

Die Schalter nebeneinander

AnbieterDer SchalterWas er stopptWorauf du achtest
VercelGit trennen, git.deploymentEnabled: false in vercel.json oder ein Ignored Build StepTrennen stoppt jeden Git-Build; die anderen beiden lassen das Repository verbunden und überspringen per RegelEin Ignored Build Step legt trotzdem ein Deployment an, das dann abgebrochen wird
NetlifyStop builds oder ein ignore-Befehl in netlify.tomlStop builds stoppt jeden Build, auch Build Hooks; ignore kann Build Hooks durchlassenDeploy-Previews für Pull Requests stoppen mit
RenderAuto-Deploy auf Off (Dashboard, autoDeployTrigger: off in render.yaml oder die API)Pushes starten keine Deploys mehr; das Repository bleibt verbundenEin Blueprint-Sync kann es wieder einschalten; Pull-Request-Previews sind eine eigene Einstellung
Cloudflare PagesProduction deployments und Preview deployments auf ausKeine Push-Builds, Previews eingeschlossenOb ein von Hand angelegtes Deployment baut, solange beide aus sind, ist nicht dokumentiert; teste es einmal

So wählst du

  • Du willst Production nach deinem Zeitplan und Previews behalten: Renders Auto-Deploy Off oder ein Vercel-Ignored-Build-Step, der VERCEL_ENV prüft, lassen Previews in Ruhe. Netlifys ignore mit CONTEXT kann dasselbe.
  • Du willst nie, dass ein Push baut: Vercels Git-Trennung, Netlifys Stop builds und Cloudflares zwei Schalter tun das, und du deployst per CLI oder Hook.
  • Du nutzt mehrere Anbieter: Eine Regel pro Anbieter ist Pflegeaufwand. Deploy Center setzt den Schalter bei jedem Anbieter von einem Ort aus und deployt dann, was sich geändert hat: deploys vercel autodeploy-off --all, deploys render autodeploy-off --all, deploys netlify autodeploy-off <site>, deploys cloudflare off <project>.

Was Deploy Center abdeckt

Vercel und Render sind standardmäßig an; Netlify, Cloudflare Pages, AWS Amplify, DigitalOcean App Platform, Coolify und jeder Deploy-Hook sind optional (deploys providers enable <host>). Die Anleitung jedes Anbieters hat die Schritte und das Rückgängigmachen: Vercel, Netlify, Render, Cloudflare Pages (alle englisch).

Diese Seite vergleicht Schalter, keine Preise. Tarife und Limits ändern sich; was ein Build dich kostet, siehst du auf den Preis- und Nutzungsseiten deines Anbieters.

Fragen

Welcher Anbieter hat den einfachsten Schalter?

Render: eine Einstellung, Auto-Deploy Off, je Dienst. Vercel bietet drei Wege und Netlify zwei, das gibt mehr Kontrolle und mehr Auswahl.

Stoppen auch Previews?

Bei Netlify und Cloudflare Pages ja, außer du behältst sie mit einer Regel oder lässt den Preview-Schalter an. Bei Render sind Pull-Request-Previews eine eigene Einstellung. Bei Vercel entscheidet der Ignored Build Step je Branch.

Kann ich jeden Schalter rückgängig machen?

Ja. Jede Anleitung hat einen Abschnitt zum Rückgängigmachen, und Deploy Center merkt sich bei Cloudflare Pages die vorigen Werte.

Reicht ein Schalter für Production?

Für Push-Builds ja. Ein Blueprint-Sync bei Render oder ein anderes Werkzeug kann trotzdem Deploys starten; deploys triggers zeigt Builds, die niemand von hier gestartet hat.

Du nutzt Vercel oder Render?

Deploy Center schaltet Auto-Deploy bei Vercel und Render mit einem Klick ab, Netlify und andere Hosts sind optional, und es deployt, was sich geändert hat, wenn du es entscheidest. Kostenlos und Open Source für macOS.
