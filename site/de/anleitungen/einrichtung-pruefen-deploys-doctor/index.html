Einrichtung prüfen: Tools, Logins, Schlüssel

deploys doctor --text prüft die Tools und Logins, die Deploy Center braucht, und gibt je eine Zeile aus: ok, off oder FIX, mit dem Befehl, der es behebt. deploys creds ergänzt, woher der Schlüssel jedes Anbieters kommt, ob er funktioniert und wie alt er ist. Beide lesen nur.

Zuletzt aktualisiert am 23. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. doctor aufrufen

deploys doctor --text
deploys doctor --text --strict     # Exit 1, wenn eine Zeile FIX sagt
deploys doctor --fix               # die Befehle zum Tippen, nichts wird ausgeführt
deploys doctor                     # dieselben Fakten als JSON

Ein Beispiel von einem frischen Rechner (die Ausgabe der CLI ist englisch):

ok   jq
ok   gh (GitHub CLI)
FIX  gh is logged in   -> gh auth login
ok   curl
ok   the settings folder is writable
     bash 5.2.21, jq 1.7
     render: {"renderKey":false,"renderKeySource":"none"}
     vercel: {"vercelCli":false,"vercelApi":false,"vercelLoggedIn":false}
off  secret-tool is missing: the keychain (keys fall back to the environment) does not work

2. Wie du es liest

  • ok: es funktioniert.
  • off: ein optionales Stück fehlt. Deploy Center läuft ohne es, mit einem Ersatz, den die Zeile nennt.
  • FIX: etwas, das du brauchst, ist nicht eingerichtet, und die Zeile endet mit dem Befehl, der es behebt.
  • Die Zeilen ohne Marke sind Fakten: Versionen und was jeder Anbieter geantwortet hat.

deploys doctor --fix listet dieselben Probleme als nummerierte Vorschläge. Es zeigt Befehle zum Tippen. Es führt sie nie aus.

3. Die Schlüssel prüfen

deploys creds                  # woher jeder Schlüssel kommt, ob er geht, wie alt er ist
deploys creds --max-age 90 --json

Es gibt eine Zeile je Anbieter aus:

PLATFORM  KEY FROM  STATE         KEY AGE  NOTE
Render    missing   NOT accepted  -
Vercel    login     NOT accepted  -

Der Schlüssel kommt aus der Umgebung, dem Schlüsselbund oder einem Login. Bei einem Schlüssel im Schlüsselbund steht auch das Alter, und einer, der älter als --max-age Tage ist, wird markiert, damit du ihn erneuerst. Der Befehl zeigt nie einen Schlüssel.

4. Wo es sich lohnt

  • Nach der Installation auf einem neuen Mac, einem CI-Runner oder Server: deploys doctor --text --strict als letzter Schritt der Einrichtung.
  • Vor einem geplanten Deploy: Ein fehlgeschlagener Login zeigt sich hier statt um 09:00. Siehe einmal am Tag deployen.
  • Wenn ein Deploy „unauthorized“ meldet: Starte zuerst creds. Meist ist ein Schlüssel abgelaufen oder umgezogen.

Fragen

Ändert deploys doctor etwas?

Nein. Es prüft und gibt aus. Nichts startet einen Build, einen Deploy oder einen Rollback ohne Klick oder einen Befehl mit --yes, und --fix zeigt nur Befehle.

Was ist der Unterschied zwischen doctor und creds?

doctor prüft Tools und Logins. creds betrifft die Schlüssel der Anbieter: woher jeder kommt, ob er akzeptiert wird und wie alt er ist.

Wird je ein Schlüssel ausgegeben?

Nein. Keiner der Befehle zeigt einen Schlüssel, und Schlüssel kommen nie auf eine Kommandozeile oder ins Journal.

Kann ich es in CI nutzen?

Ja. deploys doctor --text --strict endet mit 1, wenn eine Zeile FIX sagt.

Du nutzt Vercel oder Render?
