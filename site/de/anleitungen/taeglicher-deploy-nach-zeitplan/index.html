Einmal am Tag nach Zeitplan deployen

Führe deploys schedule daily 09:00 --when-green auf deinem Mac aus. Es richtet einen Job ein (launchd oder eine Cron-Zeile), der einmal täglich deploy-changed --yes ausführt. Ohne Mac macht ein GitHub-Actions-Workflow dasselbe auf einem Runner.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Sieh nach, bevor du planst

deploys changed                       # was live gehen würde
deploys deploy-changed --when-green   # die Liste mit CI-Urteilen; startet nichts

Führe das einige Tage von Hand aus. Entspricht die Liste deiner Erwartung, plane es.

2. Auf deinem Mac

deploys schedule daily 09:00 --when-green   # einmal täglich um 09:00, nur grüne Commits
deploys schedule status                     # ist es eingerichtet, und mit welchen Argumenten
deploys schedule off                        # entfernen

Der Job führt deploys deploy-changed --yes mit den Optionen aus, die du angegeben hast, über launchd, oder gibt die Cron-Zeile aus. Es gelten dieselben Regeln wie bei einem Deploy von Hand: Das Deploy-Fenster kann ihn ablehnen, deine pre-deploy- und post-deploy-Hooks laufen darum herum, und ein Budget aus deploys budget set hält ihn an, bevor er darüber geht.

Der Job lebt auf diesem Mac. Für einen Zeitplan, der nicht von einem Rechner abhängt, nimm einen Workflow.

3. Aus GitHub Actions

Die Datei examples/daily-deploy.yml im Repository läuft jeden Werktag und deployt alles mit Commits, die nicht live sind. Von Hand gestartet zeigt sie nur die Liste. Sie braucht gh, angemeldet über GH_TOKEN, das Token deines Anbieters (zum Beispiel VERCEL_TOKEN oder RENDER_API_KEY) und das CLI-Release-Tarball. Führe sie einmal von Hand aus und lies das Log, bevor du ihr vertraust. Siehe Deploy from CI und die GitHub-Actions-Anleitung (beide englisch).

Geplante Workflows stoppen nach 60 Tagen. GitHub schaltet einen schedule:-Workflow ab, wenn im Repository 60 Tage lang nichts passiert ist. Ein Repository, in das niemand pusht, ist genau das; der Workflow meldet sich, wenn er fehlschlägt, und du solltest ihn ab und zu prüfen.

4. Halte einen täglichen Deploy sicher

  1. Ergänze --when-green, damit ein roter Commit bis morgen wartet: nur bei grünem CI deployen.
  2. Ergänze eine Gesundheitsprüfung, die zurückrollt: automatischer Rollback.
  3. Schalte Auto-Deploy beim Anbieter ab, sonst deployen Pushes zusätzlich von selbst. deploys triggers listet Builds, die niemand von hier gestartet hat.

Fragen

Deployt Deploy Center standardmäßig nach Zeitplan?

Nein. Es deployt, wenn du Deploy drückst oder einen deploys-Befehl ausführst. Die tägliche Erinnerung in den Einstellungen ist nur eine Benachrichtigung, und nur wenn etwas wartet. Einen geplanten Deploy richtest du selbst ein.

Kann ich nur werktags deployen?

Ein Deploy-Fenster kann Wochenenden sperren, siehe die Freeze-Anleitung. Das GitHub-Actions-Beispiel läuft werktags.

Was passiert, wenn das Fenster einen Deploy ablehnt?

Der Job startet in einem geschlossenen Fenster keine Production-Deploys, außer ihm wurde --force mit einem Grund gegeben.

Wie stoppe ich ihn?

deploys schedule off entfernt den Job.

Du nutzt Vercel oder Render?

Deploy Center schaltet Auto-Deploy bei Vercel und Render mit einem Klick ab, Netlify und andere Hosts sind optional, und es deployt, was sich geändert hat, wenn du es entscheidest. Kostenlos und Open Source für macOS.
