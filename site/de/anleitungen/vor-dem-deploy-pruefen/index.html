Prüfen, was ein Deploy ausliefert: Risiko, Diff, Secrets

Führe vor einem Deploy deploys risk <project> für eine grüne, gelbe oder rote Bewertung des wartenden Diffs aus, deploys secrets <project>, um hinzugefügte Zeilen zu finden, die wie ein Schlüssel aussehen, und deploys diff <project>, um zu lesen, was sich ändert.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Lies, was sich ändert

deploys changed         # wartende Commits und PRs, je Projekt
deploys diff web        # die Commits und Dateien zwischen live und Branch
deploys notes web       # dasselbe als Release Notes (Markdown)

2. Die Risikobewertung

deploys risk web --json

Sie bewertet den Diff zwischen live und Branch (aus GitHubs Vergleich, höchstens 300 Dateien). Der schlimmste Fund bestimmt die Stufe:

FundStufe
Migrationen: migrations/, migrate/, prisma/, *.sql, schema.prisma, schema.rbrot
Lockfiles wie package-lock.json, pnpm-lock.yaml, yarn.lock, Cargo.lock, go.sumgelb
.env und .env.*gelb
Konfiguration wie vercel.json, render.yaml, Dockerfile, .github/workflows/gelb
mehr als 500 geänderte Zeilen oder 30 Dateiengelb
mehr als 3000 geänderte Zeilen oder mindestens 100 Dateienrot

deploy-changed ohne --yes nennt ein rotes Risiko neben dem Projekt. In der App zeigt eine Zeile nur bei Rot einen roten Punkt; Gelb bleibt still, und die Details nennen jeden Grund.

3. Suche nach Secrets in dem, was wartet

deploys secrets web && deploys deploy web --yes     # ein Gate in einem Skript
git diff A..B | deploys secrets --stdin             # ein Diff, den du hineinleitest

Es sieht nur die Zeilen an, die in dem, was live gehen soll, hinzugefügt wurden, mit denselben Mustern, die Logs maskieren (Schlüssel, Tokens, private Schlüssel). Es gibt Dateinamen und die maskierte Zeile aus, nie das Secret, und endet mit Exit 1, wenn es eines findet. Es braucht perl.

Kein vollständiger Scanner. deploys secrets ist ein schnelles Gate. Für gitleaks, OSV-Scanner und Semgrep auf einer frischen Kopie des Repositorys nimm deploys check start owner/repo, siehe die Scan-Docs (englisch).

4. Stelle die Prüfungen vor den Deploy

deploys plan --when-green        # die Liste mit Schätzung je Build, nichts startet
deploys risk web && deploys secrets web && deploys deploy web --yes

Ein rotes Risiko ist eine Information, keine Sperre: Du liest die Gründe und entscheidest. Kombiniere es mit CI, das grün sein muss, und einer Rollback-Prüfung.

Fragen

Stoppt ein rotes Risiko den Deploy?

Nein. Es nennt ein Risiko und die Gründe. Du entscheidest, und deploy-changed ohne --yes zeigt es neben dem Projekt.

Welche Dateien machen einen Diff rot?

Migrationen, ein Diff von mehr als 3000 Zeilen oder mindestens 100 Dateien. Lockfiles, .env-Dateien, Anbieter-Konfiguration und ein Diff über 500 Zeilen oder 30 Dateien machen ihn gelb.

Schickt secrets meinen Code irgendwohin?

Nein. Es liest den Diff auf deinem Rechner mit den Mustern, die Logs maskieren, und gibt nur Dateinamen und die maskierte Zeile aus.

Geht das auch bei GitLab?

Leite einen Diff in deploys secrets --stdin.
