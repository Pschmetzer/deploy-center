Monorepo: nur die geänderte App bauen

In einem Monorepo baut ein Push jedes verbundene Projekt, auch wenn sich nur ein Ordner geändert hat. Gib jedem Projekt eine Regel, die seine eigenen Ordner und die geteilten Pakete vergleicht: eine Überspringen-Einstellung oder einen Ignored Build Step bei Vercel, einen ignore-Befehl bei Netlify, Build Filters bei Render, Build Watch Paths bei Cloudflare Pages.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Warum ein Push alles baut

Jedes Projekt bei deinem Anbieter ist mit demselben Repository verbunden, und jedes baut bei einem Push. Eine Web-App, eine Docs-Seite und eine Admin-App in einem Repository bauen dreimal, wenn sich nur die Docs geändert haben. Eine Regel pro Projekt sagt dem Anbieter, welche Ordner für es zählen.

2. Vercel

Drei Möglichkeiten, vom kleinsten zum größten Aufwand:

  • Bei npm-, yarn- oder pnpm-Workspaces schaltest du die Einstellung ein, die ein Deployment überspringt, wenn sich das Root-Verzeichnis des Projekts und seine Abhängigkeiten nicht geändert haben (Build-Einstellungen, unter Root Directory).
  • Bei Turborepo setzt du den Ignored Build Step auf npx turbo-ignore.
  • Sonst vergleichst du die Ordner selbst:
git diff --quiet HEAD^ HEAD -- . ../../packages/ui

Exit 0 heißt: nichts hat sich geändert, Vercel überspringt den Build. HEAD^ sieht nur den neuesten Commit eines Pushes; die Anleitung zum Ignored Build Step (englisch) hat ein Skript, das stattdessen mit dem letzten Deployment vergleicht.

3. Netlify

Netlify setzt CACHED_COMMIT_REF (der Commit des letzten Builds) und COMMIT_REF (der Commit, der gebaut wird). Vergleiche die Ordner dazwischen:

# netlify.toml, im Ordner der Site
[build]
  ignore = "git diff --quiet $CACHED_COMMIT_REF $COMMIT_REF -- . ../../packages/ui"

Schlägt der Befehl fehl, etwa weil es keinen früheren Build zum Vergleichen gibt, endet er mit einem Wert ungleich 0, und Netlify baut: die sichere Richtung.

4. Render

Nutze in Settings → Build & Deploy des Dienstes die Build Filters: Pfade, die einbezogen, und Pfade, die ignoriert werden. Eine Änderung außerhalb der einbezogenen Pfade deployt nicht. Trage die geteilten Pakete, die der Dienst importiert, als einbezogene Pfade ein, sonst verpasst er eine Änderung, die ihn betrifft.

5. Cloudflare Pages

Öffne Settings → Builds & deployments und suche nach Build Watch Paths, wo du die Pfade einträgst, die einen Build starten sollen, und die, die es nicht sollen. Zeigt dein Projekt sie nicht, nimm ein Pages-Projekt pro App und stelle die Production-Deployments wie in der Cloudflare-Pages-Anleitung (englisch) ein.

6. Fallen

  • Geteilter Code. Eine Änderung in packages/ui muss jede App bauen, die es importiert. Trage geteilte Ordner in jede Regel ein.
  • Dateien im Wurzelverzeichnis. Eine geänderte Lockfile, eine Konfiguration im Root oder eine CI-Datei kann jede App betreffen. Entscheide, ob sie zählen.
  • Ein übersprungener Build ist kein Deploy. Der Anbieter bricht ihn ab, Production bleibt auf dem letzten Build. Prüfe, dass eine echte Änderung weiter baut.
  • Teste die Regel. Führe sie lokal aus und gib den Exit-Code aus, bevor du dich darauf verlässt.

Wenn Regeln zu viel sind. Soll Production einfach live gehen, wenn du es entscheidest, ist Auto-Deploy abzuschalten (englisch) ein Schalter pro Projekt statt einer Regel pro Projekt.

7. Was Deploy Center ergänzt

deploys changed zählt Commits je Projekt, und deploys explain <project> sagt, warum ein Projekt als geändert zählt oder nicht. Prüfe damit eine Regel: Nach einem Push, der einen Ordner berührt hat, sollte nur dieses Projekt wartende Commits zeigen.

Fragen

Funktioniert eine Regel bei allen Anbietern?

Nein. Jeder Anbieter liest seine eigene Einstellung, mit derselben Idee: die Ordner, von denen ein Projekt abhängt, mit dem letzten Build vergleichen.

Warum baut Vercel weiter, obwohl ich git diff eingetragen habe?

Meist schlägt das Skript fehl, oder HEAD^ hat nur den neuesten Commit eines Pushes mit mehreren angesehen. Führe es lokal aus und gib den Exit-Code aus.

Was, wenn ich ein geteiltes Paket vergesse?

Das Projekt baut nicht neu, wenn sich nur dieses Paket ändert. Trage den Paketordner in die Regel ein und halte die Liste in einem Skript, das du prüfst.

Ist Auto-Deploy abzuschalten einfacher?

Oft ja. Eine Einstellung pro Projekt ersetzt eine Regel pro Projekt, und du deployst, was sich geändert hat, wenn du es entscheidest.

Du nutzt Vercel oder Render?

Deploy Center schaltet Auto-Deploy bei Vercel und Render mit einem Klick ab, Netlify und andere Hosts sind optional, und es deployt, was sich geändert hat, wenn du es entscheidest. Kostenlos und Open Source für macOS.
