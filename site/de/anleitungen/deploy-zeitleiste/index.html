Eine Deploy-Zeitleiste: was wann geschah

deploys timeline gibt aus, was mit deinen Deploys passiert ist, neuester Tag zuerst: Deploys, Fehlschläge, Rollbacks und erzwungene Starts, je mit Uhrzeit, Projekt und Anbieter. Es liest nur das lokale Journal, braucht kein Netz und startet nichts.

Zuletzt aktualisiert am 23. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Aufrufen

Ohne Optionen zeigt es die letzten 3 Tage:

deploys timeline
deploys timeline --days 7 --project web --limit 20
deploys timeline --json

Ein ausgedachtes Beispiel (Zeiten in UTC; die Ausgabe der CLI ist englisch):

Timeline of the last 3 days (UTC)
  2026-11-23
    05:04  forced   web (Vercel): Deployed in the window "Friday": hotfix
    04:04  rollback web (Vercel): back
  2026-11-22
    04:04  deploy   web (Vercel): ok
    02:04  FAILED   api (Render): Deploy failed

2. Die Zeilen lesen

  • deploy: ein Deploy, der live ging.
  • FAILED: ein Build oder Deploy, der fehlschlug, mit gekürztem Fehlertext. Schlüssel und Tokens werden maskiert, bevor sie ins Journal kommen.
  • rollback: Production wurde auf den Deploy davor zurückgesetzt.
  • forced: ein Deploy in einem geschlossenen Zeitfenster mit --force "Grund". Der Grund steht in der Zeile, siehe die Freeze-Anleitung.

Im Journal steht nur, was Deploy Center gestartet oder aufgezeichnet hat. Ein Push, den dein Anbieter selbst gebaut hat, erscheint nicht. Das ist ein Grund, Auto-Deploy abzuschalten.

3. Eine eigene Zeile hinzufügen

Eine Notiz kommt ins Journal und erscheint in der Zeitleiste. Das hilft, wenn du einen Monat später hineinschaust:

deploys note web "Bild-CDN gewechselt"

Eine Notiz hat höchstens 200 Zeichen. Ein Text, der wie ein Schlüssel oder Token aussieht, wird abgelehnt. Der Befehl berührt keinen Anbieter.

4. Wofür es gut ist

  • Nach einem Vorfall: was wurde in den Stunden davor deployt, und gab es einen Rollback?
  • Am Montag: was hat sich am Freitag geändert, während du weg warst?
  • In einem Skript: deploys timeline --json für eine Chat-Nachricht oder ein Ticket.

Jede Zahl kommt aus dem Journal auf deinem Mac. Kein Netz, kein Aufruf beim Anbieter, nichts wird gestartet.

Fragen

Startet oder ändert deploys timeline etwas?

Nein. Es liest das Journal und gibt aus. Nichts startet einen Build, einen Deploy oder einen Rollback ohne Klick oder einen Befehl mit --yes.

Welche Zeitzone gilt?

UTC, für die Tagesüberschriften und die Uhrzeiten. Rechne bei einem Vorfall den Unterschied zu deiner Zeitzone ein.

Warum fehlt ein Deploy aus dem Dashboard meines Anbieters?

Das Journal enthält, was Deploy Center gestartet oder aufgezeichnet hat. Ein Build, den ein Git-Push oder ein anderes Werkzeug gestartet hat, steht dort nicht. deploys triggers zeigt solche Builds.

Kann ich nur ein Projekt ansehen?

Ja. --project web filtert nach Namen, --days legt fest, wie weit es zurückschaut, und --limit begrenzt die Zeilen (Standard 50).

Du nutzt Vercel oder Render?

Deploy Center schaltet Auto-Deploy bei Vercel und Render mit einem Klick ab, Netlify und andere Hosts sind optional, und es deployt, was sich geändert hat, wenn du es entscheidest. Kostenlos und Open Source für macOS.
