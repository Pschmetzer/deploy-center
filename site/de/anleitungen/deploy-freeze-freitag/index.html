Einen Deploy-Freeze für Freitagnachmittag einrichten

Lege ~/.config/deploys/window.json mit einer deny-Regel wie {"days": ["fri"], "from": "15:00"} an. In diesem Fenster starten deploys deploy und deploy-changed --yes keine Production-Deploys, außer du gibst --force "Grund" an.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Schreibe das Fenster

Die Datei ist ~/.config/deploys/window.json (oder $DEPLOYS_CONFIG/window.json). Jeder Eintrag in deny ist eine Zeit, in der Production-Deploys nicht erlaubt sind:

{
  "deny": [
    { "days": ["fri"], "from": "15:00" },
    { "days": ["sat", "sun"] },
    { "from": "22:00", "to": "06:00", "reason": "nobody is awake to fix it" },
    { "dates": ["2026-12-24", "2026-12-31"] }
  ]
}
  • days: mon bis sun. Weglassen gilt für jeden Tag.
  • dates: YYYY-MM-DD, für Feiertage.
  • from und to: Ortszeit, HH:MM. Sie stehen standardmäßig auf 00:00 und 24:00. Liegt from nach to, läuft die Regel über Mitternacht.
  • reason: der angezeigte Text. Ohne ihn wird die Regel beschrieben, zum Beispiel fri 15:00-24:00.

2. Frage, ob es offen ist

deploys window          # Open oder Closed, und welche Regel
deploys window --json   # {"denied":true,"reason":"fri 15:00-24:00",...}

deploys window endet mit Exit 1, solange das Fenster geschlossen ist; ein Skript kann daran anhalten. Mit --json endet es immer mit 0.

3. Was es sperrt und was nicht

In einem geschlossenen Fenster starten diese keine Production-Deploys: deploys deploy, deploys deploy-changed --yes, deploys vercel deploy, deploys render deploy und der Deploy-Befehl, den die App nutzt.

Diese laufen weiter, weil sie Fixes oder harmlos sind: Previews (--preview), Rollbacks und verify.

Was es nicht stoppen kann. Das Fenster schützt Deploys, die mit Deploy Center gestartet werden. Einen Push, den dein Anbieter von selbst deployt, hält es nicht auf. Schalte Auto-Deploy ab und lass den Guard (englisch) es wieder abschalten, falls es zurückkommt, damit jeder Production-Deploy durch das Fenster geht.

4. Lass einen Hotfix durch

deploys deploy-changed --yes --force "Hotfix für die Login-Seite"

Jedes so gestartete Projekt bekommt einen forced-Eintrag im Deploy-Verlauf, mit dem Fenster und deinem Grund. In der App fragt die Bestätigung zuerst nach, wenn das Fenster geschlossen ist; Trotzdem deployen … nimmt den Grund auf. Einstellungen → Deploy → Deploy-Fenster bearbeitet dieselbe Datei.

5. Ein Skript statt einer Datei

Für eine Regel, die eine Zeittabelle nicht ausdrücken kann, hält ein pre-deploy-Skript in ~/.config/deploys/hooks.d einen Start mit einem Exit ungleich 0 an:

#!/bin/sh
# keine Deploys am Freitagnachmittag
[ "$(date +%u%H)" -lt 515 ] || { echo "keine Deploys am Freitagnachmittag" >&2; exit 1; }

Mach es mit chmod 700 ausführbar. Hooks werden nur aus deinem eigenen Konfigurationsordner gelesen, nie aus einem Repository.

Fragen

Stoppt der Freeze einen Rollback?

Nein. Rollbacks, Previews und verify laufen in einem Fenster weiter, denn ein Rollback ist ein Fix.

Wie deploye ich einen Hotfix während des Freezes?

Gib --force mit einem Grund an oder nutze in der App Trotzdem deployen …. Der Grund landet im Deploy-Verlauf.

Deployt ein Push trotzdem, wenn Auto-Deploy beim Anbieter an ist?

Ja. Das Fenster schützt nur Deploys, die mit Deploy Center gestartet werden. Schalte Auto-Deploy beim Anbieter ab, damit Production-Deploys durch das Fenster gehen.

Welche Zeitzone nutzt das Fenster?

Die Ortszeit des Macs oder Rechners, der den Befehl ausführt, denn from und to sind Ortszeiten.

Du nutzt Vercel oder Render?

Deploy Center schaltet Auto-Deploy bei Vercel und Render mit einem Klick ab, Netlify und andere Hosts sind optional, und es deployt, was sich geändert hat, wenn du es entscheidest. Kostenlos und Open Source für macOS.
