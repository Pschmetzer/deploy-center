Preview-Builds für Bots bei Netlify, Cloudflare und Render vermeiden

Bei Netlify steuert ein ignore-Skript, das für Bot-Branches mit 0 endet. Bei Cloudflare Pages begrenzt du die Preview-Branches oder schaltest Previews ab. Bei Render baut ein Dienst nur den Branch, den er eingestellt hat; Bot-Branches zählen dort nur über Pull-Request-Previews, die eine eigene Einstellung haben.

Zuletzt aktualisiert am 20. November 2026 · von Patrick Schmetzer, Autor von Deploy Center

English version

1. Kenne die Branch-Namen

Bots und Agenten nutzen vorhersehbare Branch-Präfixe: dependabot/… bei Dependabot, renovate/… bei Renovate und bei Coding-Agenten das Präfix, das das Werkzeug verwendet, etwa claude/… oder cursor/…. Sieh dir die Branches in deinem eigenen Repository an und nimm diese Präfixe für die Regeln unten. Für Vercel siehe die Vercel-Anleitung (englisch).

2. Netlify: ein Ignore-Skript

Netlify führt den ignore-Befehl vor jedem Build aus: Exit 0 bricht den Build ab, Exit 1 baut. Es setzt BRANCH auf den Branch, der gebaut wird.

# netlify.toml
[build]
  ignore = "bash scripts/netlify-ignore.sh"
#!/usr/bin/env bash
# scripts/netlify-ignore.sh  -  Exit 0 = Build überspringen, Exit 1 = bauen
case "$BRANCH" in
  dependabot/*|renovate/*|claude/*|cursor/*) exit 0 ;;
esac
exit 1

Teste es lokal mit BRANCH=renovate/x bash scripts/netlify-ignore.sh; echo $?; es sollte 0 ausgeben. Die abgebrochenen Builds erscheinen weiter in der Deploy-Liste. Nutzt du zusätzlich die Build-Hook-Regel aus der Netlify-Anleitung (englisch), lege beide Prüfungen in ein Skript, denn Netlify liest einen ignore-Befehl.

3. Cloudflare Pages: Preview-Branches begrenzen

Öffne im Pages-Projekt Settings → Builds & deployments und sieh dir Preview deployments an. Bietet dein Dashboard eine Auswahl der Branches, nimm nur die Branches auf, die Menschen nutzen, oder schließe die Bot-Präfixe aus. Gibt es nur alle oder keine, stelle auf keine und öffne Previews von Hand. Cloudflare rechnet jeden Build auf ein monatliches Build-Limit an; übersprungene Previews lassen also auch Raum für die Builds, die zählen. Einzelheiten stehen in der Cloudflare-Pages-Anleitung (englisch).

4. Render: Previews haben eine eigene Einstellung

Ein Render-Dienst deployt den Branch, für den er eingerichtet ist; ein Push auf einen Bot-Branch baut ihn also nicht. Builds entstehen durch Pull-Request-Previews, eine eigene Einstellung je Dienst, durch Auto-Deploy des eigenen Branches des Dienstes und dadurch, dass Pull Requests der Bots in ihn gemergt werden. Schalte Pull-Request-Previews dort ab oder auf manuell, wo sie niemand prüft, und nimm Build Filters oder [skip render] für Commits, die keinen Build brauchen. Siehe die Render-Anleitung (englisch).

Abwägung. Ein Bot-Pull-Request ohne Preview prüfst du anhand von Diff und CI. Ist ein Dependency-Update riskant, baue es von Hand: Das ist ein Deploy, den du gewählt hast, keiner pro Push.

5. Sieh, was ein Push bauen würde

deploys hooks install setzt einen Git-Pre-Push-Hook in ein Repository. Vor jedem Push zeigt er, welche Vercel- und Render-Builds der Push starten würde; so merkst du einen bauenden Bot-Branch, bevor er baut.

Fragen

Welche Branch-Präfixe nutzen Bots?

Dependabot nutzt standardmäßig dependabot/, Renovate renovate/. Coding-Agenten nutzen ihr eigenes Präfix; sieh dir die Branches an, die sie in deinem Repository angelegt haben.

Taucht ein übersprungener Netlify-Build trotzdem auf?

Ja. Netlify bricht ihn ab, und er steht in der Deploy-Liste als abgebrochener Deploy.

Ist der Production-Branch betroffen?

Nur wenn deine Regel ihn trifft. Die Präfixe oben treffen nie main. Willst du auch Production nach deinem Zeitplan, schalte stattdessen Auto-Deploy ab.

Kann ich Previews für Pull Requests von Menschen behalten?

Ja. Die Regeln prüfen Branch-Namen; ein Pull Request von einem Branch ohne Bot-Präfix bekommt weiter seine Preview.
