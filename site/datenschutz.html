Links zu GitHub und X

Die Seite verlinkt auf GitHub (Download, Quellcode, Issues). Der Knopf „Share your number“ im Kostenrechner öffnet X (x.com) mit einem vorbereiteten Text. Erst wenn Sie einen solchen Link anklicken, werden Daten an den jeweiligen Anbieter übertragen; dort gilt dessen Datenschutzerklärung. Diese Werte sind keine personenbezogenen Daten.

Die App Deploy Center

Die App sendet keine Telemetrie und hat kein Konto bei uns; es gibt keinen Server von uns. Sie spricht mit Ihren eigenen Zugängen direkt mit Vercel, Render und GitHub, ruft für Logos und die Prüfung nach einem Deploy Ihre eigenen Websites auf und sucht einmal am Tag nach einer neuen Version (in den Einstellungen abschaltbar). Dazu lädt sie die Datei https://deploycenter.app/appcast.xml von GitHub Pages (siehe oben); übertragen werden dabei nur die technisch nötigen Daten, also IP-Adresse und Zeitpunkt, sowie eine Kennung mit dem Namen und der Version der App und der Version des Update-Werkzeugs Sparkle. Ein Systemprofil wird nicht gesendet. Gibt es ein Update und Sie installieren es, wird es von GitHub (github.com) heruntergeladen. Die App prüft vor der Installation die digitale Signatur (EdDSA) und die Signatur von Apple. Ihr Render-API-Key liegt nur im Schlüsselbund Ihres Macs. Fehler werden nur lokal in ~/Library/Logs/DeployCenter.log gespeichert.

Außerdem ruft die App die öffentlichen Statusseiten von Vercel, Render und GitHub ab (www.vercel-status.com, status.render.com, www.githubstatus.com), um Störungen bei diesen Anbietern anzuzeigen. Dabei werden keine Daten von Ihnen übertragen, nur die technisch nötigen Verbindungsdaten wie IP-Adresse und Zeitpunkt.

Weitere Dienste, nur wenn Sie sie einrichten

Die folgenden Datenflüsse sind ausgeschaltet, bis Sie die jeweilige Funktion selbst einrichten. Die Daten gehen dann direkt von Ihrem Gerät an den jeweiligen Anbieter, mit Ihrem eigenen Zugang; wir erhalten sie nicht. Für die Verarbeitung beim Anbieter gilt dessen Datenschutzerklärung. Rechtsgrundlage ist Ihre Nutzung der Funktion (Art. 6 Abs. 1 lit. b DSGVO bzw. Ihr Vertrag mit dem Anbieter). Bei Anbietern mit Sitz in den USA können Daten in die USA übertragen werden.

  • Claude in der App (Anthropic PBC, USA): Wenn Sie die Funktion einschalten und Ihren eigenen Anthropic-API-Key speichern, sendet die App auf Ihre Anfrage hin an api.anthropic.com: den Ausschnitt des Build-Logs um den ersten Fehler, oder die Titel wartender Commits und Pull Requests, oder Änderungsstatistiken und die Namen auffälliger Dateien. Bekannte Schlüssel und Passwörter werden vorher maskiert; das ist eine Hilfe, keine Garantie. Die Abrechnung läuft über Ihr Konto bei Anthropic.
  • Autofix (Anthropic PBC, USA): Wenn Sie eine Claude-Code-Routine und deren Token hinterlegen, sendet die App bzw. die CLI bei einem fehlgeschlagenen Build an api.anthropic.com: Projekt, Repository, Branch, Commit, Deploy-ID und das Ende des Build-Logs (höchstens 60 KB, maskiert). Die Routine läuft in der Cloud von Anthropic unter Ihrem Claude-Konto, liest dort Ihr Repository und öffnet einen Pull Request.
  • GitLab (GitLab Inc., USA, oder Ihre eigene GitLab-Instanz): Liegt ein Repository auf GitLab, liest die App über glab oder Ihren GITLAB_TOKEN Commits und Merge Requests von gitlab.com bzw. von der Adresse in GITLAB_HOST.
  • Weitere Hosting-Anbieter: Schalten Sie Netlify, Cloudflare Pages, AWS Amplify, DigitalOcean App Platform oder Coolify ein, spricht die App mit deren Schnittstellen (api.netlify.com, api.cloudflare.com, AWS über die aws-CLI, api.digitalocean.com, Ihre Coolify-Instanz), um Projekte zu lesen und auf Ihren Wunsch zu deployen oder zurückzurollen.
  • Deploy-Hooks und Webhooks: Eine Deploy-Hook-Adresse, die Sie hinterlegen, wird beim Deployen aufgerufen. Die Zusatzwerkzeuge für eine tägliche Zusammenfassung und den Agent-Digest senden Projektnamen, Zahlen und bei Digest auch Commit- und PR-Titel samt Autorennamen an die Webhook-Adresse, die Sie angeben (zum Beispiel Slack, Discord, Telegram oder ntfy), und legen beim Digest ein Issue in einem GitHub-Repository von Ihnen an. Empfänger ist der Dienst, den Sie wählen.

Herunterladen und Installieren

Die App, Updates und die Kommandozeile deploys werden von GitHub (github.com, GitHub-Releases) geladen, das Installationsskript install.sh von dieser Website (GitHub Pages). Installieren Sie über Homebrew, lädt Homebrew die Paketbeschreibung aus unserem Tap-Repository auf GitHub und die Datei von GitHub-Releases. Dabei verarbeitet GitHub die technisch nötigen Daten wie oben beschrieben. Homebrew selbst kann eigene, anonyme Nutzungsstatistiken senden; das regelt Homebrew, abschalten lässt es sich mit brew analytics off. Wir sehen keine Daten einzelner Downloads.

Die App Deploy Center für iPhone und iPad

Auch die iOS-App sendet keine Telemetrie, hat kein Konto bei uns und nutzt keinen Server von uns; wir erhalten keine Daten. Ihre Vercel-, Render- und GitHub-Zugangsschlüssel liegen im Schlüsselbund Ihres Geräts. Wenn Sie in der Mac-App „Mit der iPhone-App verbinden“ einschalten, legt sie diese Schlüssel in Ihren iCloud-Schlüsselbund; Apple überträgt sie Ende-zu-Ende-verschlüsselt auf Ihre Geräte mit derselben Apple-ID, wir haben darauf keinen Zugriff. Alternativ zeigt die Mac-App die Schlüssel eine Minute lang als QR-Code, den die iOS-App mit der Kamera liest; das Kamerabild verlässt das Gerät nicht. Die Schlüssel werden nur direkt an api.vercel.com, api.render.com und api.github.com gesendet, um Ihre Projekte zu lesen und auf Ihren Wunsch zu deployen oder zurückzurollen. Vor jedem Deploy und jedem Zurückrollen fragt die App nach Face ID oder dem Gerätecode; diese Prüfung übernimmt iOS, die App erhält keine biometrischen Daten. Hinweise werden als lokale Mitteilungen auf dem Gerät erzeugt. Der Demo-Modus zeigt erfundene Daten und sendet nichts.
