Scheduled deploys: cron, GitHub Actions or deploys schedule

Cron with a deploy hook is the smallest and checks nothing. A GitHub Actions schedule runs without your Mac but stops after 60 days without activity. deploys schedule runs on your Mac and applies CI, window and budget rules, but only while that Mac does the job.

Last updated 27 November 2026 · by Patrick Schmetzer, author of Deploy Center

Which to pick

  • One project, one host, no checks: cron and a hook is enough.
  • No Mac in the loop, a team repository: a workflow. Run it once by hand and read the log. Keep an eye on it, since GitHub stops scheduled workflows in quiet repositories.
  • Your own Mac, with rules: deploys schedule daily 09:00 --when-green. Set it up with the guide on a daily deploy.

Whichever you pick, turn push builds off on the host. Otherwise pushes deploy on their own as well, and the schedule is just one more deploy. deploys triggers lists builds nobody started from here.

Questions

Does Deploy Center deploy on a schedule by default?

No. A schedule is something you set up with deploys schedule or a workflow.

Which has the most checks built in?

deploys schedule, since the CI gate, the deploy window, hooks and the budget are part of deploy-changed. In a workflow you add them yourself.

Which survives my laptop being closed?

A workflow or cron on a server. The deploys schedule job lives on the Mac that set it up.

Can I combine them?

Yes. The CLI runs inside a GitHub Actions workflow, so you get a runner-based schedule with the same --when-green rule.

Use Vercel or Render too?

Deploy Center turns off auto-deploy on Vercel and Render in one click, Netlify and other hosts opt-in, and deploys what changed when you decide. Free and open source for macOS.
