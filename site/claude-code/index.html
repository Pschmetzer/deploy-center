Deploy Center + Claude Code: let the agent push, you decide what ships

Claude Code pushes many small commits, and with auto-deploy on, each one is a paid build on Vercel or Render. Deploy Center turns those builds off, ships everything waiting in one deploy when you decide, and hands failed builds back to Claude to fix.

Last updated 12 November 2026 · by Patrick Schmetzer, author of Deploy Center

Claude writes and pushes the code. Deploy Center is the other half: you decide what ships, and Claude fixes what breaks. Deploy Center is a free, open-source Mac app that works with Claude Code.

A failed build fixes itself (almost)

  1. Build fails
  2. Claude Code routine
  3. Fix PR
  4. You merge
  5. One-click deploy

Every 10 minutes Deploy Center looks for failed Vercel and Render builds. It hands each one, with the end of the build log and secrets masked, to a Claude Code routine in the cloud. Claude finds the cause, fixes it on its own branch, runs the build and opens a pull request. You review and merge; Deploy Center tells you, and you deploy the fix with one click.

  • It never merges and never deploys by itself. A person merges, and you start the deploy.
  • Rate limits: at most 2 hand-overs per project and 6 per account in 24 hours. The same failure is never handed over twice.
  • Not every PR will fix the deploy. The cloud session does not have your platform's environment variables, and a missing secret cannot be fixed in code; Claude reports that instead.

Setup and details: Auto-fix failed builds with Claude.

Many pushes, one deploy

Claude Code commits and pushes in small steps. On Vercel and Render each push builds every project connected to the repository. Turn auto-deploy off once, and the pushes wait in Deploy Center: the commits and PRs not yet live, per project and in total. Select all changed → Deploy ships the newest commit of each project. See Your agent pushes 40 times. You deploy once.

Copy for Claude

When a build fails, open its log in Deploy Center. The failing lines are red, Jump to first error takes you there, and Copy for Claude copies the project, commit and error lines as a ready fix request. Paste it into Claude Code.

Ask Claude what is waiting

The MCP server in integrations/mcp lets Claude Code ask Deploy Center what is waiting to go live, read release notes and build logs, and, only if you turn it on, deploy one project after you said yes. It is read-only by default, and there is no “deploy everything” tool.

In one click: in the app, Settings → Claude connects Claude Desktop and Claude Code to the MCP server that comes with the app (it needs Node.js 18 or newer). Deploys stay off unless you allow them there.

The Claude Code plugin brings the MCP server, a skill, four commands and a push hook. In a Claude Code session:

/plugin marketplace add Pschmetzer/deploy-center
/plugin install deploy-center@deploy-center

Then run /deploy-center:deploys-waiting, or see what the plugin contains.

By hand, from a clone of the repo:

# needs Node 18+; replace /path/to/deploy-center with your clone of the repo
cd /path/to/deploy-center/integrations/mcp && npm ci

# read-only: what is waiting, notes, logs
claude mcp add deploys -- node /path/to/deploy-center/integrations/mcp/server.mjs

# or allow single-project deploys, each one asked for first
claude mcp add deploys -e DEPLOYS_MCP_ALLOW_DEPLOY=1 -- node /path/to/deploy-center/integrations/mcp/server.mjs

Then ask Claude “what is waiting to go live?”. Keep the approval prompt on for the deploy and rollback tools.

One approval a day

The agent digest collects what your agents pushed during the day into one summary: per project, commits by agents and by people, the pull requests, and what to check first. You approve one deploy (a button in the message, or a label on the day's issue) instead of reacting to every push.

Setup

  1. Download Deploy Center and connect Vercel (your vercel CLI login) and Render (an API key in the keychain).
  2. Click Turn off auto-deploy. Claude's pushes now wait instead of building.
  3. Optional: set up Autofix in Settings → Claude → Autofix, or in the terminal:
pbpaste | deploys autofix set-token     # the routine's API token
deploys autofix routine trig_XXXXXXXX  # the routine's trigger id
deploys autofix --dry-run              # see what would be handed over
deploys autofix schedule on            # check every 10 minutes

Questions

Does Deploy Center work with Claude Code?

Yes. Claude Code pushes to GitHub as usual; Deploy Center turns off the automatic Vercel and Render builds, shows what is waiting, and deploys it when you decide. Autofix hands failed builds to a Claude Code routine.

How do I stop Claude Code from triggering a Vercel build on every push?

Turn off auto-deploy for the project, either in Vercel's Git settings or for all projects at once in Deploy Center. Claude keeps pushing; nothing builds until you deploy.

Can Claude deploy by itself?

No. Autofix opens pull requests and never merges or deploys. The MCP server is read-only by default; with deploys allowed, it deploys one project at a time and only after you confirm.
